### 数据集说明：`10abalone.data` 长什么样

打开它，前 5 行长这样（真实文件内容）：

```text
M,0.455,0.365,0.095,0.514,0.2245,0.101,0.15,15
M,0.35,0.265,0.09,0.2255,0.0995,0.0485,0.07,7
F,0.53,0.42,0.135,0.677,0.2565,0.1415,0.21,9
M,0.44,0.365,0.125,0.516,0.2155,0.114,0.155,10
I,0.33,0.255,0.08,0.205,0.0895,0.0395,0.055,7
```

**没有表头。** 第一行就是数据。这一点非常关键，后面 1.7 节会因为它踩一个坑。

九列的含义（题目已经给了，这里对齐一下口径）：

| 列号 | 题目里的名字 | 本数据集里的实际含义 | 取值范围（实测） |
|---|---|---|---|
| 0 | 性别 | `M` 雄 / `F` 雌 / `I` 幼体（未分化） | 三个字母 |
| 1 | 长度 | 最长壳长（原始数据已做统一缩放，无量纲） | 0.075 ~ 0.815 |
| 2 | 直径 | 垂直方向壳长 | 0.055 ~ 0.650 |
| 3 | 高度 | 含壳高度 | 0.000 ~ 1.130 |
| 4 | 总重量 | 整只重量 | 0.002 ~ 2.8255 |
| 5 | 皮重 | 去肉后的壳重 | 0.001 ~ 1.4880 |
| 6 | 内脏重量 | 内脏团重量 | 0.0005 ~ 0.7600 |
| 7 | 克重 | 去内脏后的肉重 | 0.0015 ~ 1.0050 |
| 8 | **年龄** | 壳上的**环数**（rings） | 1 ~ 29 |

💡 **这里有个必须提前说清楚的事**：数据集最后一列的真名是 **rings（环数）**，不是"年龄"。生物学上的通行换算关系是

$$\text{年龄（年）} \approx \text{环数} + 1.5$$

所以程序里打印的 `真实年龄: 10.0`，严格说是"10 个环"，约等于 11.5 岁。**本书为了和题目、和源码保持一致，仍然把这个数叫"年龄"**，但你心里要清楚它是什么。答辩时被问到这一点能答出来，是很加分的。

## 1.2 第一眼：数据和代码都摆在这里

在动手之前，先把"素材"摸清楚。这是所有工程任务的好习惯：**先看输入，再看输出，最后看中间。**

### 看数据

```text
【实测输出 · 数据规模】
data.shape = (4177, 9) | dtype = float64
首行 = [ 1.      0.455   0.365   0.095   0.514   0.2245  0.101   0.15   15.    ]
末行 = [ 1.      0.71     0.555   0.195   1.9485  0.9455  0.3765  0.495  12.    ]
```

注意两个细节：

1. **`dtype = float64`**。原本文件里 `sex` 是字母 `M/F/I`，读进来之后变成了数字 `1.0`。说明加载过程做了"字母 → 数字"的映射。
2. **`4177` 行**，和题目说的"共 4177 行"完全一致。这是个好消息，说明文件没被截断、也没多出表头行。

### 看各列的统计

```text
【实测输出 · 各列统计】
  sex(M=1,F=-1,I=0)  min=-1.0000 max= 1.0000 mean= 0.0529
  长度                 min= 0.0750 max= 0.8150 mean= 0.5240
  直径                 min= 0.0550 max= 0.6500 mean= 0.4079
  高度                 min= 0.0000 max= 1.1300 mean= 0.1395
  总重量               min= 0.0020 max= 2.8255 mean= 0.8287
  皮重                 min= 0.0010 max= 1.4880 mean= 0.3594
  内脏重量             min= 0.0005 max= 0.7600 mean= 0.1806
  克重                 min= 0.0015 max= 1.0050 mean= 0.2388
  环数(标签)           min= 1.0000 max=29.0000 mean= 9.9337
```

从这张表里能读出三件对后面极其重要的事：

**（1）各列的量级差了 1000 倍以上。**
`总重量` 最大 2.8255，`高度` 最大 1.13，而 `内脏重量` 最小 0.0005。
如果不做归一化，`总重量` 这一个特征就会在梯度里"喊得最大声"，其他特征几乎听不见。这就是**为什么必须归一化**。

**（2）`高度` 的最小值是 0.0000。**
一只鲍鱼不可能高度为 0——这是**脏数据**（原始 UCI 数据集里确实有几条这样的记录）。它不会让程序崩，但会让归一化的分母、后续的除法出现极端值。记住这件事，1.9 节会用到。

**（3）标签（环数）是 1 到 29 的整数，均值 9.93。**
标签**没有**被归一化（如果归一化了，范围会是 0~1）。这个观察非常重要，它决定了后面 loss 的量级是"环的平方"而不是"0.0x"。

### 看 sex 的分布

```text
【实测输出】
sex 列取值 = [-1.0, 0.0, 1.0]
sex 计数 M/F/I = [1528, 1307, 1342]
```

1528 + 1307 + 1342 = **4177**。三个数加起来正好等于总行数，说明**每一行都被成功映射了**，没有落下的。

> **Q：为什么作者要用 `1 / -1 / 0` 来编码性别，而不是用 `1 / 2 / 3` 或者 `0 / 1 / 2`？**
>
> **A：** 三个原因，一个比一个深。
>
> 1. **让均值接近 0。** 用 `1/-1/0` 时，这一列的均值是 0.0529（实测），几乎居中；用 `1/2/3` 均值会是 2 附近。神经网络对"输入均值接近 0"更友好，梯度不会一开始就被推偏。
> 2. **对称性。** 雄 `+1`、雌 `-1` 在数值上是对称的，模型学到的权重符号可以直接解释成"雄性与雌性的差异方向"。用 `1/2` 就没有这种对称。
> 3. **避免虚假的大小关系。** 用 `0/1/2` 时，模型会以为 `I(2) > F(1) > M(0)`，即"幼体比雌性大、雌性比雄性大"——这是**不存在的顺序**。用 `1/-1/0` 至少不会引入"1 < 2 < 3"这种单调暗示（虽然它仍然不是完美方案，1.17 节会讲更好的做法）。
>
> ⚠️ 但注意：这套编码经过归一化后会发生"位移"，`I` 会从 0 变成 0.5，夹在 `F(0.0)` 和 `M(1.0)` 中间。这个副作用我们 1.9 节专门讲。

## 1.3 整体框架：七个模块，各管一段

把源码从头扫一遍，你会看到的"骨架"是这些东西（**先别看细节，只看函数名和它们的关系**）：

```text
load_data(file_path)              → 读文件，返回矩阵
normalize_data(train, test)       → 归一化，返回两个新矩阵
class DatasetProvider             → 按批吐数据
class MLP(nn.Layer)               → 网络结构
preprocessing()                   → 把上面几步串起来
accuracy(pred, true)              → 算 R²（决定系数）
debug_DatasetProvider()           → 调试用（打印每批形状）
main()                            → 主流程
```

### 模块职责表

| 模块 | 一句话职责 | 输入 | 输出 | 对应题号 |
|---|---|---|---|---|
| `load_data` | 把纯文本变成数字矩阵 | 文件路径 | `(4177, 9)` 数组 | 10-1 |
| `normalize_data` | 把各列压到同一量级 | 训练/测试矩阵 | 两个新矩阵 | 10-2 |
| `DatasetProvider` | 把矩阵切成小批，边训练边取 | 矩阵 + 批大小 | `(64,8)` / `(64,1)` | 10-3 |
| `MLP` | 定义网络有几层、每层多宽 | 输入维度 | 一层层堆起来的网络 | 11-3 |
| `preprocessing` | 装配套餐：加载 → 切分 → 归一化 | 无 | 训练/测试矩阵 + 极值 | 10-1~3 |
| `accuracy` | 算 R²：预测解释了多少标签波动 | 预测值、真实值 | 一个数：1 完美、0 等于瞎猜、可为负 | 11-4 |
| `main` | 总导演：训练、评估、保存、推理 | 无 | 屏幕输出 + 模型文件 | 11-2~6 |

### 这个结构好在哪

**它把"数据怎么来"和"模型怎么算"彻底隔开了。**

`main()` 里从头到尾没有出现过一个文件名、一次 `open()`、一个 `for i in range(4177)`。它只知道"我手上有 `train_data`，我可以 `for batch_x, batch_y in train_provider`"。

> **Q：为什么不把所有代码都塞进 `main()` 里？反正程序只跑一次。**
>
> **A：** 因为你要**调试**，而调试需要"只跑一小段"。
>
> 举个真实的场景：训练 loss 一直不降，你怎么知道是数据坏了还是网络坏了？如果全塞在 `main()` 里，你只能一遍遍跑完整流程（100 轮），然后靠猜。
>
> 而分开写之后，你可以单独做这件事：
>
> ```python
> data = load_data('10abalone.data')
> print(data[:3])          # 数据对不对？
> ```
>
> 三行代码、0.1 秒，就能排除"数据读错了"这个可能。**能单独测试的代码，才是能修的代码。**
>
> 这也是为什么源码里还留着一个 `debug_DatasetProvider()`——它就是作者给自己留的"只测一层"的开关。

## 1.4 先别写代码：把这个程序"跑挂"一次

这是本书一个刻意的安排。**在学怎么写之前，先看它怎么坏。**

因为真实的编程有 80% 的时间在处理"它为什么不工作"，而不是"怎么让它工作"。

### 直接跑原始文件

```text
【实测输出 · 原样运行 preprocessing()】
-> FileNotFoundError: [Errno 2] No such file or directory: 'abalone.data'
```

程序在第一行就死了。为什么？

看看源码，这两个地方自相矛盾：

```python
def load_data(file_path='10abalone.data'):     # ← 默认参数写的是 10abalone.data
    ...
```

```python
def preprocessing():
    raw_data = load_data('abalone.data')       # ← 这里传的是 abalone.data
```

而你的目录里，文件叫 **`10abalone.data`**（实测确认）。

```text
【实测输出 · 目录里真实存在的文件】
-rw-r--r-- 1 cswar 197121  191873 Nov 14 21:36 10abalone.data
```

**所以这是一个真实的 bug：默认参数被显式实参覆盖了，而且实参写错了名字。**

> **Q：这是不是说明写这份代码的人水平不行？**
>
> **A：** 不是，恰恰相反——这说明了**真实代码的样子**。
>
> 注意 `load_data` 的默认参数是**对的**（`'10abalone.data'`）。很可能是这样发生的：作者一开始用默认参数调试，跑通了；后来为了"显式一点"，在 `preprocessing()` 里补了个实参，手打的时候漏了 `10` 两个字符。**默认参数从此再也没被用到**，所以这个错误一直藏着。
>
> 这类 bug 有个专门的名字：**死代码掩盖活 bug**。它给你的启示是：
> 1. 默认参数一旦所有调用点都显式传参，它就变成了"装饰品"，别指望它能救你；
> 2. 报错信息第一句就是答案（`No such file or directory: 'abalone.data'`），**先读报错，再读代码**，能省 90% 的时间。

### 修好它

改法有两条路，**推荐第二条**：

```python
# 路线 A：改调用点
def preprocessing():
    raw_data = load_data('10abalone.data')
```

```python
# 路线 B：删掉多余的实参，让默认值生效（本书采用）
def preprocessing():
    raw_data = load_data()          # 用默认参数 '10abalone.data'
```

路线 B 更好的原因：**文件名只在源码里出现一次**。将来文件改名，你只需要改一个地方——而路线 A 有两处要改，其中一处你一定会忘。

> ⚠️ 但路线 B 也有代价：`load_data()` 从此**只能**读 `10abalone.data`。如果以后要读别的文件，就没法传参了。所以更工程化的写法是把文件名提到最上面当常量：
>
> ```python
> DATA_FILE = '10abalone.data'      # 只在这一处出现
>
> def preprocessing():
>     raw_data = load_data(DATA_FILE)
> ```
>
> 这样既只有一个"真相来源"，又保留了传参能力。1.19 节的完整代码就是这么写的。

## 1.5 第一块砖：一行文本 → 一串数字

在写任何函数之前，先解决最小的问题：**给你一行文本，你怎么把它变成能算数的东西？**

```python
line = 'M,0.455,0.365,0.095,0.514,0.2245,0.101,0.15,15'
parts = line.split(',')
print('parts =', parts)
print('parts[0] =', repr(parts[0]), '| 类型 =', type(parts[0]).__name__)
print('len(parts) =', len(parts))
```

**【实测输出】**
```text
parts = ['M', '0.455', '0.365', '0.095', '0.514', '0.2245', '0.101', '0.15', '15']
parts[0] = 'M' | 类型 = str
len(parts) = 9
```

`split(',')` 把一行按逗号切开，得到一个**字符串列表**。注意两个事实：

1. **长度是 9**，和题目说的"每行 9 列"对上。
2. **全部是字符串**。连 `'0.455'` 也是字符串，不是数字。

第 2 点是最容易出事的地方。字符串不能做算术：

```python
print("float('0.455') =", float('0.455'))
print("float('0.455') + 1 =", float('0.455') + 1)
try:
    print('0.455' + 1)
except TypeError as e:
    print("'0.455' + 1 ->", type(e).__name__ + ':', e)
try:
    print(float(''))
except ValueError as e:
    print("float('') ->", type(e).__name__ + ':', e)
try:
    print(float('M'))
except ValueError as e:
    print("float('M') ->", type(e).__name__ + ':', e)
```

**【实测输出】**
```text
float('0.455') = 0.455
float('0.455') + 1 = 1.455
'0.455' + 1 -> TypeError: can only concatenate str (not "int") to str
float('') -> ValueError: could not convert string to float: ''
float('M') -> ValueError: could not convert string to float: 'M'
```

两种错误，含义完全不同，**必须分清楚**：

| 报错类型 | 什么时候出现 | 说明什么 |
|---|---|---|
| `TypeError` | 字符串 + 数字 | 你**忘了转**，是逻辑错误 |
| `ValueError` | `float('')` / `float('M')` | 你**转了但内容不是数**，是数据问题 |

> **Q：为什么 `float('')` 报 `ValueError` 而不是 `TypeError`？**
>
> **A：** 因为 `''` 确实是字符串，类型是对的——`float()` 接受的参数类型本来就是 `str`。错的是**内容**：空字符串没有数值含义。Python 用 `TypeError` 表示"类型不对"，用 `ValueError` 表示"类型对但值不行"。
>
> 分清这一点有实际意义：写异常处理时，抓到 `ValueError` 说明是数据脏了（该跳过这一行），抓到 `TypeError` 说明你的代码写错了（该改代码，不能靠 try 糊过去）。

### 拼成一行

现在要把"性别数字"和"后面 8 个数"拼成**一个列表**：

```python
a = 1.0
rest = [0.455, 0.365]
print('[a] + rest =', [a] + rest, '| 长度 =', len([a] + rest))
try:
    print(a + rest)
except TypeError as e:
    print('a + rest ->', type(e).__name__ + ':', e)
```

**【实测输出】**
```text
[a] + rest = [1.0, 0.455, 0.365] | 长度 = 3
a + rest -> TypeError: unsupported operand type(s) for +: 'float' and 'list'
```

**必须写成 `[a] + rest`，不能写 `a + rest`。** 因为列表的 `+` 是"拼接两个列表"，而 `float + list` 没有定义。`[a]` 的作用就是**把单个值包成一个只有一个元素的列表**，这样两边都是列表才能拼。

> 这就是源码里 `data.append([sex_val] + num_vals)` 那一行的由来。看起来绕，其实是被 Python 的类型规则逼出来的。

### 一个隐藏的坑：忘了 float 会怎样

**如果不转 float，直接 `np.array(整个列表)` 会发生什么？** 这是本节最值钱的一个实验：

```python
import numpy as np

mixed = [[1.0, '0.455'], [-1.0, '0.53']]
arr = np.array(mixed)
print('dtype =', arr.dtype)
print(arr)
```

**【实测输出】**
```text
dtype = <U32
[['1.0' '0.455']
 ['-1.0' '0.53']]
```

**注意 `dtype = <U32`。** 这是"长度不超过 32 的 Unicode 字符串"。numpy 发现你有数字有字符串，为了"兼容"，**把整个数组都变成了字符串**。

`1.0` 变成了 `'1.0'`，`-1.0` 变成了 `'-1.0'`。程序**不会报错**，它会安安静静地把你的数值数据全毁掉。等你后面做乘法的时候才会莫名其妙地出错。

> **Q：这个坑为什么特别危险？**
>
> **A：** 因为它**不报错**。
>
> 报错的 bug 是好 bug，你 5 秒钟就能定位。**静默错误的 bug 是坏 bug**，它可能让你花一整天怀疑是网络结构有问题、是学习率不对、是数据不够。
>
> 记住一条排查原则：**当深度学习模型"怎么调都不收敛"时，第一件事是打印 `X.dtype` 和 `X[:3]`。** 十次里有三次，问题就出在数据本身。

## 1.6 `load_data` 是怎么一步步长出来的

现在可以写完整的加载函数了。但**不要一次写完再调试**——那样一旦出错，你不知道是哪一步错的。

正确的方式是**分四步长出来**，每步都能跑、都能看结果。

### 第 1 版：只把行读出来

```python
import csv

def load_v1(path, limit=3):
    with open(path, 'r') as f:
        reader = csv.reader(f)
        n = 0
        for row in reader:
            print('  ', row, '| 类型', type(row).__name__, '| 长度', len(row))
            n += 1
            if n >= limit:
                break

load_v1('10abalone.data')
```

**【实测输出】**
```text
   ['M', '0.455', '0.365', '0.095', '0.514', '0.2245', '0.101', '0.15', '15'] | 类型 list | 长度 9
   ['M', '0.35', '0.265', '0.09', '0.2255', '0.0995', '0.0485', '0.07', '7'] | 类型 list | 长度 9
   ['F', '0.53', '0.42', '0.135', '0.677', '0.2565', '0.1415', '0.21', '9'] | 类型 list | 长度 9
```

这一步确认了：**每行是 9 个字符串，没有表头，格式统一**。

> **Q：`csv.reader` 和 `open(...).readlines()` 有什么区别？为什么要用 `csv` 模块？**
>
> **A：** 对这个文件来说，两者结果一样；但 `csv.reader` 多做三件事：
>
> 1. **正确处理引号**。如果某个字段是 `"Zhang, San"`（值里含逗号），`split(',')` 会切成三份，`csv.reader` 会正确地当成一份。
> 2. **正确处理不同换行符**。Windows 的 `\r\n`、Linux 的 `\n`，`csv` 都帮你抹平了（实测确认 `CRLF` 文件读出来是 `['M,0.455', 'F,0.53']`，没有残留 `\r`）。
> 3. **按需读取**。`csv.reader` 是**迭代器**，不占内存；`readlines()` 会把整个文件读进内存。4177 行不算大，但 4177 万行就不一样了。
>
> 习惯上用 `csv` 读 CSV/TSV，比手写 `split` 稳。

### 回头对照源码

源码里的 `load_data` 就是第 4 版，只是把 `for x in row[1:]` 展开成了显式循环，并且把注释写在了行尾：

```python
# ============================================================
# 模块 ①：load_data —— 把文本文件读成 (4177, 9) 的数字矩阵
# ------------------------------------------------------------
# 输入：file_path  数据文件路径（默认 10abalone.data）
# 输出：numpy 数组，形状 (行数, 9)，dtype=float64
#     第 0 列  = 性别（M→1.0  F→-1.0  I→0.0）
#     第 1~7 列 = 长度/直径/高度/总重量/皮重/内脏重量/克重
#     第 8 列  = 环数（也就是题目说的"年龄"）
# ============================================================
def load_data(file_path='10abalone.data'):
    data = []                                   # 用来攒每一行，最后一次性转成数组

    with open(file_path, 'r') as f:             # 以只读方式打开；with 会自动关闭文件
        reader = csv.reader(f)                  # 把文件包装成"一行一行地吐列表"的迭代器

        for row in reader:                      # 每次拿到一行，row 是字符串列表，如 ['M','0.455',...]
            if not row:                         # 空行（文件末尾的空换行）→ 列表是 []，跳过
                continue

            sex = row[0]                        # 第 0 列是性别，是字母，需要手工映射成数字
            if sex == 'M':                      # 雄性
                sex_val = 1.
            elif sex == 'F':                    # 雌性
                sex_val = -1.
            elif sex == 'I':                    # 幼体（Infant，未分化）
                sex_val = 0.
            else:
                break                           # ⚠️ 遇到不认识的字母就"整份文件停止读取"

            num_vals = []                       # 用来攒这一行后面 8 个数值
            for x in row[1:]:                   # row[1:] 表示"从第 1 个到最后一个"
                num_vals.append(float(x))       # 字符串 → 浮点数（这一步不做，整列数据就没法算）

            data.append([sex_val] + num_vals)   # 把 1 个性别 + 8 个数值拼成一行（共 9 个）

    return np.array(data)                       # 列表的列表 → numpy 二维数组
```

> **Q：为什么 `load_data` 最后返回的是 numpy 数组，而不是继续用 Python 的列表？**
>
> **A：** 因为后面要做三件列表做不了（或做起来很慢）的事：
>
> 1. **整列取最小/最大值**：`train_data[:, :8].max(axis=0)` 一行搞定。用列表得写双重循环。
> 2. **整列做算术**：`(train_data[:, i] - min_vals[i]) / range_vals[i]` 一行搞定。列表得 `for` 一遍。
> 3. **按行号批量取**：`self.feature[batch_indices]` 一次取出 64 行。列表得写列表推导式。
>
> 一句话：**numpy 数组支持"整块运算"，列表只支持"逐个运算"。** 这是 numpy 存在的全部理由。

## 1.7 `load_data` 的四个坑（全部实测）

这段代码能跑，但它**非常脆弱**。我拿四种"看起来很正常"的坏数据喂给它，看它怎么反应。

### 坑 1：文件开头有一行表头 → 读到 0 行

```text
【实测输出】
  加表头 -> 读到行数 = (0,)
```

**注意 `(0,)` 这个形状。** 它不是报错，是一个"空数组"。程序"成功"返回了，但里面一行数据都没有。

原因：表头第一列是 `'Sex'`，不等于 `'M'/'F'/'I'`，于是走到 `else: break`，**第一行就停了**。

如果你没检查形状，直接往后走，会在归一化那一步炸掉——而且报的错和"没读到数据"看起来毫无关系。这就是"错误在 A 处产生，在 B 处爆炸"。

### 坑 2：中间混进一行非法数据 → 后面全部静默丢弃

```text
【实测输出】
  中间插一行 X,... -> 总行数 = 3 （原文 6 行数据，实际只读到 3 行）
    -> 后面 3 行被静默丢弃，没有报错
```

这是四个坑里**最阴的一个**。程序读到 `X` 就 `break` 了，后面的 3 行**根本没被看**。没有警告、没有日志、没有任何痕迹。

> **Q：这里为什么用 `break` 而不是 `continue`？用 `continue` 不是更好吗？**
>
> **A：** 作者的意图应该是"**如果遇到非数据行，说明文件读完了，收工**"——这是把 `break` 当"正常结束"用。
>
> 但这个意图只在"非法行一定出现在末尾"时成立。如果非法行出现在中间（比如手工编辑数据时插了一行），`break` 会把**后面所有有效数据一起扔掉**。
>
> `continue` 的行为是"跳过这一行，接着读下一行"，会得到一个"尽量多读"的结果。两种写法各有适用场景：
>
> | 写法 | 语义 | 适合 |
> |---|---|---|
> | `break` | 到此为止，后面不要了 | 文件有明确的结束标记 |
> | `continue` | 跳过坏行，继续 | 数据可能有零星脏行 |
>
> **工程上更稳的做法是：记一个计数器，遇到坏行就 `+= 1` 并 `continue`，最后打印"跳过了 N 行"。** 这样脏数据不会静默消失，你在日志里能看见它。1.19 节的改进版就是这么写的。

### 坑 3：某行少一列 → 悄悄变成 8 列

```text
【实测输出】
  少一列 -> shape = (1, 8)
```

一行本该 9 个字段，实际只有 8 个（少了环数）。程序照样 `append`，于是这一行只有 8 个数。

如果**所有**行都少一列，`np.array` 会给你一个 `(n, 8)` 的数组，程序继续往下跑——然后你会在"取标签 `data[:, -1]`"时，**把"克重"当成"年龄"**。

如果**只有部分行**少一列，问题会更直接：

```text
【实测输出】
ValueError: setting an array element with a sequence. The requested array has an inhomogeneous shape after 1 dimensions. The detected shape was (2,) + inhomogeneous part.
```

`inhomogeneous shape` 的意思是"形状不齐"——numpy 2.x 拒绝把"3 个数一行、8 个数一行"的参差列表变成矩阵。**这条报错是好事**，它救了你的命。

> **Q：`(1, 8)` 那个情况为什么不报错？**
>
> **A：** 因为只有一行，`[[1.0, 0.455, ..., 0.15]]` 里每个子列表长度都是 8，形状"齐"，numpy 认为没问题。
>
> 于是你得到了一个"每行 8 列"的数组。接着 `data[:, -1]` 取到的是**第 7 列（克重）**，而不是年龄。
>
> 模型照样训练，loss 照样下降，各项指标照样能算出一个"说得过去"的数——**你什么都看不出来**，除了"这个模型怎么预测出来的年龄都是 0.2 左右"。
>
> **教训：加载完数据，一定要打印 `shape` 并核对它是不是 `(4177, 9)`。** 这是最便宜的一道保险。

### 坑 4：某个字段是空的 → ValueError

```text
【实测输出】
  空字段 -> ValueError: could not convert string to float: ''
```

行是 `M,0.455,,0.095,...`，中间有个空字段。`float('')` 直接炸。

这个坑好在**它会报错**，而且报错信息（`could not convert string to float: ''`）已经把原因说清楚了。你只需要给 `float()` 包一层 `try`，决定"跳过这行"还是"填 0"。

### 四个坑的总结表

| 坑 | 程序表现 | 危险程度 | 怎么防 |
|---|---|---|---|
| 表头 | 返回 `(0,)`，后续才炸 | ⚠️⚠️⚠️ | 检查 `shape[0] > 0` |
| 中间非法行 | 静默丢弃后面的行 | ⚠️⚠️⚠️⚠️ 最阴 | 用 `continue` + 计数器 |
| 少一列（全部） | `(n, 8)`，语义错位 | ⚠️⚠️⚠️⚠️ | 断言 `shape[1] == 9` |
| 少一列（部分） | `ValueError: ... inhomogeneous` | ⚠️ 好事 | 不用管，它会叫 |
| 空字段 | `ValueError: could not convert` | ⚠️ | `try/except` 或预清洗 |

> **这四张坑，随便踩一个，就是三个小时的调试。** 而防住它们只需要三行代码：
>
> ```python
> assert arr.ndim == 2,        '读出来的不是二维数组'
> assert arr.shape[1] == 9,    '列数不对，检查文件格式'
> assert arr.shape[0] > 0,     '一行都没读到，检查文件名/表头'
> ```
>
> `assert` 的意思是"我坚信这里必须成立，否则立刻停下"。它比让你在 100 轮训练之后才发现问题要善良得多。

## 1.8 为什么一定要归一化（手算一遍）

现在数据读进来了，形状 `(4177, 9)`。第二件事是**归一化**。

先别急着看代码，看这组数字（1.2 节实测的极值表）：

```text
  高度      min= 0.0000  max= 1.1300
  总重量    min= 0.0020  max= 2.8255
  内脏重量  min= 0.0005  max= 0.7600
```

三个特征都在描述"鲍鱼有多大/多重"，但**数值范围差了三个数量级**。

### 不归一化会怎样

神经网络的第一层算的是 $z = w_1x_1 + w_2x_2 + \dots + w_8x_8 + b$。

假设 `总重量` 这一列的取值在 0~2.8，`内脏重量` 在 0~0.76。为了让 `总重量` 对结果有影响，权重 $w$ 的量级可以在 0.1 附近；但要让 `内脏重量`（数值小 3 倍）产生同样的影响，$w$ 就得大 3 倍。

结果是：**同一个学习率，对不同特征来说"太大"或"太小"。** 学习率一调大，数值大的那几列瞬间把梯度炸掉；一调小，数值小的那几列几乎学不动。

直观一点说：**这就像让 8 个人同时喊话，其中一个人拿喇叭。** 你不把喇叭收掉，就永远听不清其他 7 个人在说什么。

### 归一化做什么

**最小-最大归一化**（min-max normalization）：

$$x' = \frac{x - x_{\min}}{x_{\max} - x_{\min}}$$

效果：把每一列都压到 `[0, 1]`，最小值变 0，最大值变 1。于是 8 个特征"音量"一样了。

### 手算验证

拿首行 `[1.0, 0.455, 0.365, 0.095, 0.514, 0.2245, 0.101, 0.15, 15.0]` 和训练集的极值，一列一列算：

```text
【实测输出 · 首行归一化手算】
  列0 sex    (1.0000 - -1.0000) / 2.0000 = 1.00000000
  列1 长度     (0.4550 - 0.0750) / 0.7400 = 0.51351351
  列2 直径     (0.3650 - 0.0550) / 0.5950 = 0.52100840
  列3 高度     (0.0950 - 0.0000) / 1.1300 = 0.08407080
  列4 总重量    (0.5140 - 0.0020) / 2.8235 = 0.18133522
  列5 皮重     (0.2245 - 0.0010) / 1.4870 = 0.15030262
  列6 内脏重量   (0.1010 - 0.0005) / 0.7595 = 0.13232390
  列7 克重     (0.1500 - 0.0015) / 1.0035 = 0.14798206
```

而程序打印出来的首行是：

```text
【实测输出 · 源码打印】
[ 1.          0.51351351  0.5210084   0.0840708   0.18133522  0.15030262
  0.1323239   0.14798206 15.        ]
```

**逐位对上了。** 注意最后一列 `15.` 没变——因为它是标签（环数），**不该被归一化**。这一点 1.9 节会专门讲。

> **Q：为什么归一化是"减去最小值再除以范围"，而不是"直接除以最大值"？**
>
> **A：** 直接除以最大值（$x' = x / x_{\max}$）也能把数据压到 `[0,1]`，但有个毛病：**它不保证最小值落在 0**。
>
> 举个例子，如果某列的最小值是 0.5、最大值是 1.13，直接除以后范围变成 `[0.44, 1.0]`——依然离 0 很远。8 个特征各自"离 0 多远"不一样，就没法真正对齐。
>
> 减最小值的作用是**把整列平移到从 0 开始**，这一下才让所有特征站在同一条起跑线上。所以标准写法一定是 $(x - x_{\min}) / (x_{\max} - x_{\min})$。

## 1.9 归一化的三个关键细节

源码只用了 17 行，但里面有三个"不注意就会错"的决定。

```python
# ============================================================
# 模块 ②：normalize_data —— 最小-最大归一化
# ------------------------------------------------------------
# 输入：train_data / test_data  两个 (n, 9) 数组，最后一列是标签
# 输出：归一化后的两个新数组（**返回的是新数组，不修改传入的**）
# 关键：只用"训练集"的极值去缩放"测试集"，绝不能用测试集的极值
# ============================================================
def normalize_data(train_data, test_data):
    train_data = train_data.copy()      # 先复制一份，避免把调用者手里的原始数据改掉
    test_data = test_data.copy()        # 同理

    feature_num = train_data.shape[1] - 1   # 9 列里前 8 列是特征，最后 1 列是标签 → 8

    max_vals = train_data[:, :feature_num].max(axis=0)   # 每一列的最大值，得到长度 8 的数组
    min_vals = train_data[:, :feature_num].min(axis=0)   # 每一列的最小值，得到长度 8 的数组

    range_vals = max_vals - min_vals    # 每一列的"跨度"

    range_vals[range_vals == 0] = 1     # 防止某列全是同一个数 → 跨度为 0 → 除以 0 → NaN
    for i in range(feature_num):        # 逐列处理（只处理前 8 列，标签不动）
        train_data[:, i] = (train_data[:, i] - min_vals[i]) / range_vals[i]
        test_data[:, i] = (test_data[:, i] - min_vals[i]) / range_vals[i]
                                        # ⚠️ 注意测试集用的也是 min_vals[i] / range_vals[i]
                                        #    也就是"训练集的"极值，不是测试集自己的
    return train_data, test_data
```

### 细节 1：为什么要 `copy()`

`train_data = train_data.copy()` 看起来是废话（自己赋值给自己），其实**不是**。

Python 里 numpy 的切片是**视图**，不是副本：

```python
import numpy as np

base = np.arange(12.).reshape(4, 3)
view = base[:2]
view[0, 0] = 999.
print('base 第 0 行 =', base[0])
```

**【实测输出】**
```text
base 第 0 行 = [999.   1.   2.]
```

**改了 `view`，`base` 也变了。** 因为 `view` 只是"指向同一块内存的另一个名字"。

所以 `preprocessing()` 里传进来的 `train_raw` 如果是 `raw_data[:offset]`（一个视图），那么归一化时就地改 `train_data[:, i]`，**会把 `raw_data` 一起改掉**。

后果很具体：`preprocessing()` 后面还要用 `train_raw` 算 `min_vals` 和 `max_vals` 返回给调用者。如果前面已经把它改成 0~1 了，你返回的就是"归一化后的极值"（0 和 1），而不是原始极值——**语义全错，而且不报错**。

实测一下不加 `copy()` 的版本：

```python
import numpy as np

def normalize_bad(train, test):
    feature_num = train.shape[1] - 1
    mx = train[:, :feature_num].max(axis=0)
    mn = train[:, :feature_num].min(axis=0)
    rng = mx - mn
    rng[rng == 0] = 1
    for i in range(feature_num):
        train[:, i] = (train[:, i] - mn[i]) / rng[i]
        test[:, i] = (test[:, i] - mn[i]) / rng[i]
    return train, test

a = np.array([[1., 10., 20.], [-1., 30., 40.]])
b = a[:1].copy()
print('调用前 a =')
print(a)
normalize_bad(a, b)
print('调用后 a =')
print(a)
```

**【实测输出】**
```text
调用前 a =
[[ 1. 10. 20.]
 [-1. 30. 40.]]
调用后 a =
[[ 1.  0. 20.]
 [ 0.  1. 40.]]
```

`10` 和 `30` 变成了 `0` 和 `1`。**原始数据被就地改写了，而且调用者完全不知道。**

一行 `.copy()` 就修好了。

> **Q：为什么加了 `copy()` 之后就没问题了？**
>
> **A：** 因为 `x.copy()` 会**申请一块新的内存**，把内容复制进去。之后 `train_data[:, i] = ...` 改的是新内存，和原来的数组再无关系。
>
> 判断一个操作是"改自己"还是"返回新的"，是 numpy 里最重要的一项技能。经验法则：
> - **带 `=` 的赋值语句**（`arr[i] = ...`、`arr[a:b] = ...`、`arr.sort()`）→ **原地改**。
> - **返回值的函数**（`arr.copy()`、`arr + 1`、`np.sort(arr)`）→ **产生新数组**。
>
> 唯一的坑就是**切片**：`arr[0:2]` 是视图，看着像"取出了一段"，其实是"给同一块内存起了个名"。

### 细节 2：为什么测试集必须用训练集的极值

源码这两行是本节的核心：

```python
train_data[:, i] = (train_data[:, i] - min_vals[i]) / range_vals[i]
test_data[:, i]  = (test_data[:, i]  - min_vals[i]) / range_vals[i]
                                        # ↑ 同一个 min_vals[i]，不是测试集自己的最小值
```

**测试集用的是 `min_vals[i]`，也就是训练集的最小值。**

> **Q：如果测试集用自己的极值归一化，会发生什么？凭什么不行？**
>
> **A：** 两句话：
>
> **第一，这是自欺欺人。** 用测试集自己的极值，意味着你在训练阶段就"偷看"了测试数据的分布。这叫**数据泄漏**（data leakage）。模型在测试集上的成绩会虚高，因为它看到的数据"被调整成了模型最舒服的形状"。
>
> 举个极端例子：测试集只有 10 条数据，其中一条特别大。用自己的极值归一化后，这条变成了 1.0，其他 9 条被挤到 0.1 附近——**测试集的形状被这 10 条数据自己决定了**，和训练时看到的形状完全不一样。
>
> **第二，真实世界里你拿不到测试集的极值。** 模型上线后，来一条新的鲍鱼数据，你要预测它的年龄。这时候"未来数据的最大值"是不存在的。你唯一能用的，就是训练时记下来的 `min_vals` 和 `range_vals`。
>
> **所以正确做法是：归一化的参数（min、range）属于"模型的一部分"，训练时算好存下来，推理时原样复用。** 这也是为什么 `preprocessing()` 要把 `min_vals, max_vals` 一起 `return` 出去——虽然这份源码里 `main()` 没有接住它们（见 1.19 节的讨论）。

### 细节 3：`range_vals[range_vals == 0] = 1` 在防什么

如果某一列**所有值都相同**，那么 `max == min`，跨度是 0，`(x - min) / 0` 会得到 `nan`（不是报错，是 `nan`）：

```python
import numpy as np

x = np.array([[1., 5.], [1., 5.]])
mn = x[:, :2].min(axis=0)
mx = x[:, :2].max(axis=0)
with np.errstate(divide='ignore', invalid='ignore'):
    bad = (x - mn) / (mx - mn)
print('结果 =', bad.ravel(), '| 含 nan =', np.isnan(bad).any())
```

**【实测输出】**
```text
结果 = [nan nan nan nan] | 含 nan = True
```

**`nan` 是深度学习里最可怕的错误**：它不会报错，但会顺着梯度传播，几轮之后你的 loss 就变成 `nan`，然后所有参数都变成 `nan`，然后模型彻底死掉。而你只能看到 `Train Loss=nan`，完全不知道是哪一列引起的。

源码的写法 `range_vals[range_vals == 0] = 1` 把跨度 0 换成 1，于是 `(x - min) / 1 = 0`（因为 `x == min`）。**结果这一列全变成 0，但至少是有限的数，不会污染网络。**

实测确认：

```text
【实测输出】
  第 3 列（高度）两行都是 5.0 -> range=0
  归一化后第 3 列 = [0. 0.] （源码用 range=1 兜底，全变 0，不是 NaN）
```

> 顺带一提：全变成 0 意味着"这一列信息被彻底丢弃了"。**这是对的**——一列如果所有样本都相同，它本来就携带不了任何区分信息。

### 一个必须点出来的副作用：sex 列也被归一化了

`feature_num = 8`，循环 `for i in range(8)` 把**第 0 列（性别）也归一化了**。

原来 `M=1, F=-1, I=0`，归一化之后：

```text
【实测输出】
  原始 sex 取值 = [0.0, 0.5, 1.0]
  归一化后 sex 取值 = [0.0, 0.5, 1.0] (min=-1, range=2)
  含义: M->1.0  F->0.0  I->0.5，也就是说"雌雄同体"被放在了中间！
```

（上面第一行打印的是已经归一化过的训练集，所以直接看到 `[0.0, 0.5, 1.0]`。）

**`I`（幼体）从 0 变成了 0.5，夹在 `F(0.0)` 和 `M(1.0)` 正中间。**

这引入了一个**虚假的中间位置**：模型会倾向于认为"幼体介于雌雄之间"。生物学上没错（幼体确实未分化），但从"类别编码"的角度看，这是**把标称变量当成了有序变量**。

这就是 1.17 节要做独热编码实验的原因。先记住这个隐患。

### 还有一个容易漏掉的观察：标签**没有**被归一化

看上面打印的首行，最后一列是 `15.`，原封不动。

```text
【实测输出】
np.array_equal(归一化后的第 8 列, 原始的第 8 列) = True
-> 说明标签列一个数都没变
```

**这是对的，也是必须的。** 但很多同学会在这里犯一个致命的错：把标签也归到 `[0,1]`。

> **Q：如果我把标签也归一化了，会发生什么？**
>
> **A：** 三件坏事，一件比一件严重。
>
> **① loss 的量级失去意义。** 现在 `MSELoss` 是 3.34，意思是"平均错了 1.83 个环的平方"。如果标签被压到 0~1，loss 会变成 0.004 这种数——看起来"降了好多倍"，其实只是单位变了。你会误以为模型进步了。
>
> **② 硬指标直接失效——但源码的 `accuracy`（R²）不会。** 这两种指标在这里表现完全不同，实测对比：
>
> ```text
> 【实测输出 · 同一份预测，把标签从"环"缩放到 [0,1]】
>   MSE（环）= 3.3409  ->  归一化后 = 0.010311   （数字变了 324 倍，量级失去意义）
>   |误差|<=1 的比例 = 0.5251  ->  归一化后 = 1.0000   （直接失效：0.036 的误差也算"<=1"）
>   R²（accuracy）   = 0.538270 ->  归一化后 = 0.538270 （不变）
> ```
>
> 为什么 R² 不变？看公式就明白：$R^2 = 1 - \dfrac{\sum(\hat y - y)^2}{\sum(y - \bar y)^2}$，分子分母**用的是同一个单位**，标签乘一个常数，分子分母同乘它的平方，一约就没了。**R² 是无量纲指标**——不管你用环、用月、还是归一化后的 0~1，它说的都是"解释了多少比例的波动"这一件事。
>
> 这提醒你两件事：换指标时，**像"误差 ≤1 环"这种带单位的硬标准必须跟着换单位**，否则会闹出"全部判对"的笑话；而 R² 这类比例指标天生免疫单位变换——这也是回归任务普遍用它报成绩的原因之一。
>
> **③ 推理时还得反归一化。** 模型输出 0.31，你得乘回 28 加 1 才是环数。多一步就多一个出错的地方。
>
> **结论：回归任务里，输入要归一化，标签通常保持原单位。** 只有标签量级大到让 loss 溢出（比如预测房价，单位是元，数值上百万）时，才考虑缩放标签——R² 不会因此变化，但你打印的 loss、以及"误差 ≤1"这类带单位的硬指标，全部要同步换算。

## 1.10 第三件事：为什么需要"数据集提供器"

数据读好了、缩好了，为什么不能**直接整个喂进去**？

### 因为"全量梯度下降"太慢也太糙

数据是 `(3341, 8)`。最朴素的做法是每一步都用全部 3341 条算一次梯度：

```text
用全部数据算一次梯度：
  → 梯度非常准（因为样本多）
  → 但一次只能更新 1 次参数
  → 100 轮 = 只更新 100 次
```

而 **小批量（mini-batch）** 的做法是每次拿 64 条：

```text
用 64 条算一次梯度：
  → 梯度有点抖（因为样本少）
  → 但一轮能更新 53 次
  → 100 轮 = 更新 5300 次
```

**5300 次更新 vs 100 次更新**，差距是天壤之别。

这个"抖"其实还是好事：梯度带噪声，反而更容易跳出不好的局部区域。这也是为什么几乎所有的深度学习训练都用 mini-batch。

### 手算一遍：一轮有多少批

```python
n = 3341
for bs in [64, 16, 1]:
    steps = list(range(0, n, bs))
    print(f'n={n} bs={bs} -> 批数={len(steps)} 最后起点={steps[-1]} 末批大小={min(bs, n - steps[-1])}')
```

**【实测输出】**
```text
  n=3341  bs=64  -> range(0,3341,64) 长度=53 最后起点=3328 末批大小=13
  n=3341  bs=16  -> range(0,3341,16) 长度=209 最后起点=3328 末批大小=13
  n=3341  bs=1   -> range(0,3341,1) 长度=3341 最后起点=3340 末批大小=1
  n=836   bs=64  -> range(0,836,64) 长度=14 最后起点=832 末批大小=4
```

**`3341 / 64 = 52.2`，向上取整是 53。** 前 52 批各 64 条（共 3328 条），最后一批只剩 `3341 - 3328 = 13` 条。

> **Q：最后一批只有 13 条，会不会有问题？**
>
> **A：** 不会，但要意识到它的影响。
>
> 13 条样本算出来的梯度，噪声比 64 条大得多。而 `MSELoss` 默认是 `mean`（除以样本数），所以 batch 大小不影响 loss 的量级——这是好事。
>
> 真正的影响在**训练时的指标统计**上：`epoch_acc += acc` 然后除以 `n_batches`（53），等于给了最后那个"13 条的小批"和"64 条的大批"**同样的权重**。严格说这是个小的加权误差，但影响极小，业界普遍这么写。
>
> 如果想更严谨，可以按样本数加权：`epoch_acc += acc * batch_x.shape[0]`，最后除以总样本数。属于"知道就行"的细节。

### 提供器要解决的两个问题

| 问题 | 朴素做法 | 提供器的做法 |
|---|---|---|
| 怎么切成批 | 每轮手动写 `for s in range(0, n, bs)` | `for x, y in provider` 自动切 |
| 怎么打乱顺序 | 每轮手动 `np.random.shuffle` | 构造时传 `shuffle=True` |

**提供器 = 一个"能反复遍历、每次遍历自动切批+洗牌"的对象。**

这就是它在源码里长这样（77 行）的全部野心。

## 1.11 `DatasetProvider` 逐行拆：`__iter__` + `yield` 到底在干什么

```python
# ============================================================
# 模块 ③：DatasetProvider —— 数据集提供器
# ------------------------------------------------------------
# 作用：把 (n, 9) 的矩阵切成一批一批 (bs, 8) + (bs, 1)
# 用法：for batch_x, batch_y in provider:
# 特点：每调用一次 __iter__（也就是每开始一轮 for），就重新洗一次牌
# ============================================================
class DatasetProvider:

    def __init__(self, data, batch_size=16, shuffle=True):
        self.feature = data[:, :-1]     # 前 8 列 → 特征，形状 (n, 8)
        self.label   = data[:, -1:]     # 最后 1 列 → 标签，形状 (n, 1)
                                        # ⚠️ 写成 -1:（带冒号）而不是 -1
                                        #    -1  → 形状 (n,)   一维
                                        #    -1: → 形状 (n, 1) 二维，和模型输出对齐
        self.batch_size = batch_size    # 每批多少条
        self.shuffle = shuffle          # 要不要打乱
        self.num_samples = self.feature.shape[0]   # 样本总数 n

    def __iter__(self):
        indices = np.arange(self.num_samples)      # [0, 1, 2, ..., n-1]

        if self.shuffle:
            np.random.shuffle(indices)             # 原地打乱 → [37, 5, 892, ...]

        for start_idx in range(0, self.num_samples, self.batch_size):
            end_idx = min(start_idx + self.batch_size, self.num_samples)
            batch_indices = indices[start_idx:end_idx]     # 取出这一批的"行号"

            yield self.feature[batch_indices], self.label[batch_indices]
                                        # yield = "边跑边吐"，吐完一批暂停，等下一次要
```

### 先讲清 `-1` 和 `-1:` 的区别

这是初学者最容易迷迷糊糊混过去的一行：

```python
import numpy as np

m = np.arange(12).reshape(4, 3)
print('m[:, -1]  =', m[:, -1],  '| shape =', m[:, -1].shape)
print('m[:, -1:] =', m[:, -1:].ravel(), '| shape =', m[:, -1:].shape)
```

**【实测输出】**
```text
m[:, -1]  = [ 2  5  8 11] | shape = (4,)
m[:, -1:] = [ 2  5  8 11] | shape = (4, 1)
```

**值完全一样，形状差一个维度。**

- `m[:, -1]` → `(4,)`：**一维**，形状像一根线。
- `m[:, -1:]` → `(4, 1)`：**二维**，形状像一个竖着的表格。

为什么要 `(n, 1)`？因为模型的输出是 `(64, 1)`（64 条样本，每条 1 个预测值）。如果标签是 `(64,)`，`pred - true` 会发生**广播**：`(64,1) - (64,)` → `(64, 64)`，得到一个 64×64 的矩阵，然后 loss 变成一个巨大的数。**这不会报错，只会让训练彻底跑偏。**

> **Q：那为什么不写 `data[:, -1].reshape(-1, 1)`，那样不是更清楚吗？**
>
> **A：** 可以，效果一样。`-1:` 只是更短的写法，而且它是一段**连续的切片**，在内存里不需要额外操作（`reshape` 有时会触发复制）。
>
> 但可读性上 `reshape(-1, 1)` 更明确。**本书建议：自己写代码时用 `reshape(-1, 1)`，读别人代码时认识 `-1:` 就行。**

### `yield` 是什么：一个能"暂停"的函数

`__iter__` 里有 `yield`，这个函数就变成了**生成器（generator）**。它的行为和普通函数完全不同：

- 普通函数：`return` 一次，函数结束。
- 生成器：`yield` 一次，**暂停在那一行**，把值交出去；下次再要，**从暂停的地方继续**。

看一个最小案例：

```python
class Tiny:
    def __init__(self):
        self.n = 0

    def __iter__(self):
        print('  -> __iter__ 被调用了')
        for i in range(3):
            print('  -> 准备 yield', i)
            yield i

t = Tiny()
print('第一次 for:')
for x in t:
    print('  拿到', x)
print('第二次 for（再迭代一次）:')
for x in t:
    print('  拿到', x)
```

**【实测输出】**
```text
第一次 for:
  -> __iter__ 被调用了
  -> 准备 yield 0
  拿到 0
  -> 准备 yield 1
  拿到 1
  -> 准备 yield 2
  拿到 2
第二次 for（再迭代一次）:
  -> __iter__ 被调用了
  -> 准备 yield 0
  拿到 0
  -> 准备 yield 1
  拿到 1
  -> 准备 yield 2
  拿到 2
```

**看清两件事：**

1. **`yield 0` 之后，`for` 循环体先执行**（打印"拿到 0"），然后才回到 `__iter__` 里继续到 `yield 1`。这就是"暂停—恢复"。
2. **第二次 `for` 时，`__iter__` 被重新调用了一遍**（第二次打印"`__iter__` 被调用了"）。所以里面的 `np.random.shuffle(indices)` 会**再洗一次牌**。

第 2 点就是"每个 epoch 自动重新打乱"的实现原理——**不需要在训练循环里写任何洗牌代码**，只要 `for ... in provider` 每轮重新执行，`__iter__` 就会自动跑一遍。

### 实测：批次形状

```text
【实测输出 · DatasetProvider 拆分与批形状】
num_samples = 3341
feature.shape = (3341, 8) | label.shape = (3341, 1)
batch 数 = 53
前 3 个 batch 形状 = [((64, 8), (64, 1)), ((64, 8), (64, 1)), ((64, 8), (64, 1))]
最后一个 batch 形状 = ((13, 8), (13, 1))
各 batch 样本数之和 = 3341
```

`(3341, 8)` 和 `(3341, 1)` 正好对应"8 个特征、1 个标签"。53 个 batch、最后 13 条，和 1.10 节手算完全一致。

### 实测：洗牌真的每次都在洗

```text
【实测输出 · 用连续列观察洗牌效果】
3 个 epoch 的第一个样本长度 = [0.7905, 0.3851, 0.5203]
互不相同 = True
```

（这里必须用**长度**这种连续取值的列。如果用 sex 列观察，因为只有 3 个取值，很容易连着几次抽到同一个，看不出效果——我第一次就是被这个坑骗了。）

### 实测：一轮是否"不重不漏"

```text
【实测输出 · 一个 epoch 的覆盖性】
累计行数 = 3341 | 训练集行数 = 3341
命中唯一行号个数 = 3341 | 是否无重复 = True
是否恰好覆盖 0..3340 = True
```

**一个 epoch 恰好把 3341 条各看一遍，不多不少。** 这是检验提供器写对没写对的最好方法。如果这里出现"覆盖 3300 条"或"有重复"，说明切片算错了。

### 实测：`shuffle=False` 时顺序固定

```text
【实测输出】
两次迭代的第一个样本第 0 列 = 1.0 1.0 | 相同 = True
与原始第一行第 0 列一致 = True
两个 epoch 的 batch 首样本序列是否相同 = True
```

不开洗牌时，每一轮都从第 0 行开始，顺序完全一样。这在**调试**时非常有用（可复现），在**训练**时通常不好（每轮看到的顺序一样，容易形成固定的梯度模式）。

### 两个值钱的 Q&A

> **Q：`indices = np.arange(...)` 为什么写在 `__iter__` 里面，而不是 `__init__` 里？**
>
> **A：** 因为**洗牌必须每一轮重新做一次**。
>
> 如果写在 `__init__` 里，那么对象创建时洗一次牌，之后无论迭代多少次，`indices` 都是那一个固定的顺序。`shuffle=True` 就白设了——你会看到"每轮顺序完全一样"，和 `shuffle=False` 没区别。
>
> 这条规则可以推广成一句话：**"每个 epoch 应该重置的东西，放在 `__iter__` 里；整个生命周期只算一次的东西，放在 `__init__` 里。"**
>
> 比如 `self.feature`、`self.label` 是只算一次的（切分数据），放在 `__init__`；`indices` 是每轮都要重洗的，放在 `__iter__`。

> **Q：`np.random.shuffle(indices)` 有没有返回值？`indices = np.random.shuffle(indices)` 这样写对吗？**
>
> **A：** **不对，这是个经典 bug。**
>
> `np.random.shuffle` 是**原地修改**，返回值是 `None`。写成 `indices = np.random.shuffle(indices)`，`indices` 就变成了 `None`，下一行 `indices[start:end]` 会报 `TypeError: 'NoneType' object is not subscriptable`。
>
> 实测确认原地修改的性质：
>
> ```text
> 【实测输出】
>   洗牌后 a = [2 8 4 9 1 6 7 3 0 5]
>   b 是同一个对象吗 = True | b = [2 8 4 9 1 6 7 3 0 5]
>   a 是否被原地改动 = True
> ```
>
> （`b = a` 之后洗 `a`，`b` 跟着变——说明确实是同一块内存被改了。）
>
> 类似的还有 `list.sort()`（原地，返回 `None`）vs `sorted(list)`（返回新列表）。**记住：函数名是动词原形、没有返回值提示的，多半是原地操作。**

## 1.12 提供器的两个行为特征（决定训练效果）

### 特征 1：不设种子，每次跑结果不同

```text
【实测输出】
两次取首个样本长度 = 0.8581 0.4595 | 不同 = True
```

这既是好事也是坏事：

- **好事**：每次训练看到的数据顺序不同，相当于一种"数据增强"，模型更鲁棒。
- **坏事**：**结果不可复现**。你昨天跑出 Test Acc(R²)=0.4863，今天跑出 0.4502，你没法判断是"改了代码变好了"还是"运气好"。

> 这就是为什么 1.19 节的完整代码里加了这两行：
>
> ```python
> np.random.seed(2026)      # 固定 numpy 的随机（影响洗牌）
> paddle.seed(2026)         # 固定 paddle 的随机（影响权重初始化）
> ```
>
> 加上之后，两次运行的**每一个数字都完全一样**（1.15 节有实测证明）。
>
> **做实验的基本纪律：一次只改一个变量。** 不固定种子，你就永远不知道"变化"是谁带来的。

### 特征 2：`shuffle=True` 时，标签和特征永远同步

这一点必须验证，因为如果切片错了（比如特征用了一份索引、标签用了另一份），模型会"看着 A 的特征去猜 B 的年龄"，loss 会卡在某个值下不去，而你完全看不出原因。

```text
【实测输出 · 特征与标签对齐抽查】
第 0 条特征在训练集里的行号 = [0]
该行标签 = 15.0 | batch 里的标签 = 15.0
```

**对上了。** 原理很简单：`self.feature[batch_indices]` 和 `self.label[batch_indices]` 用的是**同一个 `batch_indices`**，所以必然同步。

> **Q：那如果我想故意打乱标签（做"标签置换检验"，看模型是不是在瞎猜），该怎么改？**
>
> **A：** 只洗标签、不洗特征。可以这样：
>
> ```python
> provider = DatasetProvider(data, batch_size=64, shuffle=True)
> provider.label = np.random.permutation(provider.label)   # 只打乱标签的行顺序
> ```
>
> R² 的"零分线"就是**无脑猜均值**。所以这个检验在 R² 口径下的判读标准很清晰：如果打乱标签后 R² 还能维持正常水平，说明模型的成绩跟规律无关，**根本没学到东西**；如果 R² 掉到 0 以下，说明正常成绩里确实有真东西。实测：
>
> ```text
> 【实测输出 · 标签置换对照（20 轮，种子 2026）】
>   正常训练 -> Test Acc (R²) = 0.4863
>   打乱标签 -> Test Acc (R²) = -0.0925   （负数 = 比无脑猜均值还差）
> ```
>
> 这个技巧叫**标签置换检验**（label permutation test），是判断"模型是否真的学到了规律"最便宜的方法。

## 1.13 网络结构：`MLP` 是怎样搭起来的

### 先看要解决的数学问题

我们要找一个函数 $f$，输入 8 个数（性别、长度、直径……），输出 1 个数（环数）。

这就是**回归**（regression）：输出是连续值，不是类别。

### 形状怎么流转

```text
输入        (64, 8)      64 条样本，每条 8 个特征
  │
  ├─ Linear(8 → 128) ──► (64, 128)     把 8 个特征"展开"成 128 个中间量
  ├─ ReLU            ──► (64, 128)     负数砍成 0（非线性）
  │
  ├─ Linear(128 → 64) ─► (64, 64)      收窄
  ├─ ReLU            ──► (64, 64)
  │
  ├─ Linear(64 → 32) ──► (64, 32)      再收窄
  ├─ ReLU            ──► (64, 32)
  │
  └─ Linear(32 → 1)  ──► (64, 1)       压成 1 个数 = 预测的环数
```

**"128 → 64 → 32 → 1"是一个漏斗。** 先宽后窄，是深度学习里最常见的结构之一：宽的地方负责"提取足够多的特征组合"，窄的地方负责"逐步压缩成一个结论"。

### 代码

```python
import paddle
import paddle.nn as nn

# ============================================================
# 模块 ④：MLP —— 多层感知机（Multilayer Perceptron）
# ------------------------------------------------------------
# 结构：8 → 128 → 64 → 32 → 1
#       3 个隐藏层（128/64/32），每层后接 ReLU 激活
#       最后 1 层不加激活，直接输出一个实数（回归任务）
# ============================================================
class MLP(nn.Layer):                    # 继承 nn.Layer，才有"参数管理"能力
    def __init__(self, input_dim):      # input_dim = 特征个数 = 8
        super().__init__()              # 必须先调父类构造函数，否则参数注册不上
        self.net = nn.Sequential(       # Sequential = "按顺序串起来执行"
            nn.Linear(input_dim, 128),  # 第 1 层：8 → 128，含权重 (8,128) 和偏置 (128,)
            nn.ReLU(),                  # 激活：负数变 0，正数不变
            nn.Linear(128, 64),         # 第 2 层：128 → 64
            nn.ReLU(),
            nn.Linear(64, 32),          # 第 3 层：64 → 32
            nn.ReLU(),
            nn.Linear(32, 1),           # 输出层：32 → 1，⚠️ 后面不接激活
        )

    def forward(self, x):               # 前向传播：数据怎么流过这个网络
        return self.net(x)              # 交给 Sequential 依次执行
```

### 实测：模型长什么样

```text
【实测输出 · print(model)】
MLP(
  (net): Sequential(
    (0): Linear(in_features=8, out_features=128, dtype=float32)
    (1): ReLU()
    (2): Linear(in_features=128, out_features=64, dtype=float32)
    (3): ReLU()
    (4): Linear(in_features=64, out_features=32, dtype=float32)
    (5): ReLU()
    (6): Linear(in_features=32, out_features=1, dtype=float32)
  )
)
```

**注意层是用数字编号的：`(0)` 到 `(6)`，一共 7 项。** 3 个 Linear + 3 个 ReLU + 1 个输出 Linear = 7。这个编号后面在模型文件里会以 `net.0.weight`、`net.2.weight`……的形式再出现一次（1.18 节）。

### 实测：参数量

```text
【实测输出 · 参数清单】
参数总量 = 11521
   linear_0.w_0 (8, 128) 元素数 1024
   linear_0.b_0 (128,) 元素数 128
   linear_1.w_0 (128, 64) 元素数 8192
   linear_1.b_0 (64,) 元素数 64
   linear_2.w_0 (64, 32) 元素数 2048
   linear_2.b_0 (32,) 元素数 32
   linear_3.w_0 (32, 1) 元素数 32
   linear_3.b_0 (1,) 元素数 1
```

**手算核对一遍**（这一步强烈建议你拿笔在纸上算，比看十遍代码有用）：

| 层 | 权重形状 | 权重个数 | 偏置个数 | 小计 |
|---|---|---|---|---|
| Linear(8, 128) | 8 × 128 | 1024 | 128 | **1152** |
| Linear(128, 64) | 128 × 64 | 8192 | 64 | **8256** |
| Linear(64, 32) | 64 × 32 | 2048 | 32 | **2080** |
| Linear(32, 1) | 32 × 1 | 32 | 1 | **33** |
| | | | **合计** | **11521** |

**1152 + 8256 + 2080 + 33 = 11521**，和程序打印的一模一样。

> **Q：为什么 `Linear(8, 128)` 的权重形状是 `(8, 128)` 而不是 `(128, 8)`？**
>
> **A：** 因为 Paddle 用的是"**输入维度在前，输出维度在后**"的约定，前向计算是 $y = xW + b$，其中 $x$ 是 `(batch, 8)`，$W$ 是 `(8, 128)`，矩阵乘法 `(batch,8) @ (8,128)` 得到 `(batch,128)`。**中间那个 8 要对齐，才能乘起来。**
>
> 注意 PyTorch 的 `nn.Linear(in, out)` 内部存的权重也是 `(out, in)`，计算时转置。**不同框架的存储习惯不一样**，但接口签名都是 `Linear(输入维, 输出维)`。看形状时永远先看 `in_features` / `out_features`，别猜。

### 实测：每一层的形状变化

```python
import paddle
import paddle.nn as nn
import numpy as np

net = nn.Sequential(nn.Linear(8, 128), nn.ReLU(), nn.Linear(128, 64), nn.ReLU(),
                    nn.Linear(64, 32), nn.ReLU(), nn.Linear(32, 1))
x = paddle.randn([64, 8])          # 假装有 64 条样本
print('输入 =', tuple(x.shape))
h = x
for i, layer in enumerate(net):
    h = layer(h)
    print(f'第 {i} 层 {layer.__class__.__name__:<8} -> {tuple(h.shape)}')
print('最终输出 =', tuple(h.shape))
```

**【实测输出】**
```text
输入 = (64, 8)
第 0 层 Linear   -> (64, 128)
第 1 层 ReLU     -> (64, 128)
第 2 层 Linear   -> (64, 64)
第 3 层 ReLU     -> (64, 64)
第 4 层 Linear   -> (64, 32)
第 5 层 ReLU     -> (64, 32)
第 6 层 Linear   -> (64, 1)
最终输出 = (64, 1)
```

**`ReLU` 不改变形状**（它只是个逐元素的函数：`max(0, x)`）。只有 `Linear` 会改变形状。

### 三个必须想清楚的设计问题

> **Q1：题目要求"至少 3 层"，这个网络算几层？**
>
> **A：** 取决于你怎么数，答案是 **4 个 Linear 层**（或 3 个隐藏层 + 1 个输出层）。
>
> - 按 `Linear` 数：`Linear(8,128)`、`Linear(128,64)`、`Linear(64,32)`、`Linear(32,1)`，共 **4 层**。
> - 按"隐藏层"数：前 3 个是隐藏层，最后一个是输出层，共 **3 个隐藏层**。
> - 如果把 ReLU 也算"层"：共 7 层。
>
> **不管怎么数，都满足"至少 3 层"**，所以这一条要求是安全的。答辩时推荐说"4 层全连接、3 个隐藏层"——最不容易被挑刺。

> **Q2：为什么最后一层 `Linear(32, 1)` 后面不加 ReLU？**
>
> **A：** 因为 **ReLU 会把负数变成 0**，而我们要预测的环数虽然都是正数，但网络在训练过程中"中间输出"完全可能是负数。
>
> 更关键的是：**加了 ReLU，输出就被限制在 $[0, +\infty)$，而且梯度在负半轴恒为 0。** 如果某个样本的预测值一开始是负的（很可能，因为权重随机初始化），ReLU 会把梯度直接掐断，这个样本就**永远学不动**了（这叫"神经元死亡"）。
>
> 一般规则：
> - **回归任务**（输出任意实数）→ 最后一层**不加**激活。
> - **二分类**（输出 0~1 概率）→ 加 `Sigmoid`。
> - **多分类**（输出各类概率）→ 加 `Softmax`。
>
> 本题是回归，所以裸着输出。

> **Q3：128 / 64 / 32 这三个数是怎么定的？为什么不是 100 / 50 / 25？**
>
> **A：** 说实话——**凭经验，没有公式。** 但有几条可操作的依据：
>
> 1. **惯例是 2 的幂。** 100/50/25 也能跑，但 GPU 对 2 的幂更友好（显存对齐、指令向量化），实测通常快一点点。
> 2. **不要第一层就太窄。** 输入只有 8 维，第一层给 128，是"先把 8 个特征充分组合"；如果第一层只有 16，表达能力不够。
> 3. **逐层减半是一种常见的漏斗比例。** 128→64→32 每层减半，既压缩了信息，又不至于一步砍太狠。
> 4. **参数量要匹配数据量。** 这里 11521 个参数、3341 条训练样本，比例约 3.4 : 1，还算健康。如果只把第一层改成 1024（其余不变），参数量会涨到 **76929**（约 6.7 倍）；如果把整条链放大成 `1024-512-256`，会到 **665601**（约 58 倍）。用 3341 条数据去喂 66 万个参数，必然过拟合。
>
> 💡 **可操作的调参顺序**：先固定一个"看起来合理"的结构跑通 → 画训练曲线 → 如果欠拟合（训练 loss 也降不下去）就加宽 → 如果过拟合（训练 loss 降、测试 loss 升）就收窄或加正则。**不要一上来就纠结 128 还是 130。**

## 1.14 两个"裁判"：`MSELoss` 和 `accuracy`

网络输出的是一个**数**，真实值也是一个**数**。怎么判断"错得多不多"？

需要两个东西：

- **`MSELoss`（损失函数）**：给训练用的。它必须**可求导**，因为要靠它算梯度。
- **`accuracy`（准确度）**：给人看的。它只需要"好懂"，不需要可导。

### 裁判一：MSELoss（均方误差）

$$\text{MSE} = \frac{1}{n}\sum_{i=1}^{n}(\hat{y}_i - y_i)^2$$

"预测值和真实值差多少，平方，然后取平均。"

**为什么要平方？** 两个原因：

1. **正负误差不抵消。** 如果直接平均 `(pred - true)`，+3 和 -3 会互相抵消成 0，看起来"完美预测"。
2. **大错罚得重。** 差 1 罚 1，差 2 罚 4，差 10 罚 100。模型会优先去修正那些错得离谱的样本。

实测一下它的三种模式：

```python
import paddle
import paddle.nn as nn
import numpy as np

a = paddle.to_tensor(np.array([[1.], [2.], [3.]], dtype=np.float32))   # 预测
b = paddle.to_tensor(np.array([[2.], [4.], [3.]], dtype=np.float32))   # 真实
print('pred =', a.numpy().ravel(), '| true =', b.numpy().ravel())
print('逐元素平方误差 =', ((a - b) ** 2).numpy().ravel())
print('nn.MSELoss()       =', nn.MSELoss()(a, b).item())
print("nn.MSELoss('sum')  =", nn.MSELoss(reduction='sum')(a, b).item())
print("nn.MSELoss('none') =", nn.MSELoss(reduction='none')(a, b).numpy().ravel())
```

**【实测输出】**
```text
pred = [1. 2. 3.] | true = [2. 4. 3.]
逐元素平方误差 = [1. 4. 0.]
nn.MSELoss()       = 1.6666667461395264
nn.MSELoss('sum')  = 5.0
nn.MSELoss('none') = [1. 4. 0.]
```

**手算验证**：三个平方误差是 1、4、0，和是 5，平均是 $5/3 = 1.666\ldots$。程序给的是 `1.6666667461395264`，最后几位不对是因为 **float32 的精度只有约 7 位有效数字**。

> **Q：为什么 `1.6666667461395264` 不等于精确的 `1.6666666666...`？**
>
> **A：** 因为数据是 `float32`，不是 `float64`。
>
> `float32` 只有 23 位用来存小数部分，能表示的精度大约是 $2^{-23} \approx 1.19 \times 10^{-7}$。所以它能给出的最接近 $5/3$ 的值就是 `1.6666667`（后面那些 `461395264` 是二进制转十进制的"尾巴"）。
>
> 这提醒你：**深度学习里所有的数都是近似的。** 别去纠结 loss 的最后 5 位小数，也别写 `if loss == 0:` 这种判断——永远用 `abs(loss) < 1e-6`。

`reduction` 参数的含义：

| 取值 | 返回 | 什么时候用 |
|---|---|---|
| `'mean'`（默认） | 一个数，已除以元素个数 | 绝大多数情况，**源码用的就是它** |
| `'sum'` | 一个数，是总和 | 需要和 batch 大小解耦时 |
| `'none'` | 不归约，逐个返回 | 想自己加权、或想看每个样本的误差 |

**记住默认是 `'mean'`。** 这一点很重要：它意味着 **batch_size 从 64 改成 16，loss 的量级不会变**。如果默认是 `'sum'`，改成 16 之后 loss 会变成原来的 1/4，你就会误以为"模型突然变好了"。

### 这个 loss 的数值到底意味着什么

训练到 100 轮时，测试集 `Test Loss = 3.3409`。这个数字大不大？

```text
【实测输出 · 基线对照】
  训练集标签 均值 = 10.0401 方差 = 11.1262
  测试集标签 均值 = 9.5084 方差 = 7.2356
  若永远预测训练集均值，测试集 MSE = 7.5183
  实测模型 Test Loss = 3.3409 -> RMSE = 1.8278 环
  基线 RMSE = 2.742 环
```

**这是本节最重要的一段。** 它做了两件事：

**① 把 MSE 换算回"环"。** $\sqrt{3.3409} = 1.8278$，意思是模型的**典型误差大约是 1.8 个环**。这样一说，你立刻就知道这模型"能用但不够好"——误差 1.8 个环，相当于年龄误差 1.8 年左右。

**② 找了一个"笨蛋基线"做对比。** 最笨的预测器是"不管输入什么，都输出训练集的平均值 10.04"。它的 MSE 是 7.5183（RMSE 2.742 环）。

对比：模型 3.3409 vs 基线 7.5183。**模型把误差降低了一半多。** 这说明它确实学到了东西，不是瞎猜。

> **Q：如果模型的 loss 比 7.5183 还大，说明什么？**
>
> **A：** 说明**模型还不如直接猜平均值**。这通常意味着：
> 1. 训练没收敛（学习率太小，或轮数不够）；
> 2. 数据没归一化（数值范围太乱，梯度炸了）；
> 3. 标签取错了列（比如把"克重"当成"年龄"，那 loss 会小得离谱，因为克重都在 0~1）。
>
> **这就是为什么要先算基线**：没有基线，3.34 这个数你根本不知道是好是坏。**"降低 50%"永远比"达到 3.34"更有说服力。**

### 裁判二：`accuracy` —— R²，回归任务的"标准成绩单"

分类任务里，"准确率"很好定义：预测的类别 == 真实的类别，就算对。

但回归呢？预测 9.87、真实 10.0，算对还是算错？差 0.13 算好，那差 1.3 呢？

**源码用的是统计学里回归任务的标准指标：$R^2$（决定系数，R-squared）**：

```python
# ============================================================
# 模块 ⑤：accuracy —— R²（决定系数）
# ------------------------------------------------------------
# 思路：先算"最笨的预测器"（永远猜均值）的总平方误差 SS_tot，
#       再算模型的总平方误差 SS_res。R² = 1 - SS_res / SS_tot
#       含义：模型把"猜均值"的误差消化掉了多少比例
# 评分：R² = 1    完美预测
#       R² = 0    和无脑猜均值一样（没学到东西）
#       R² < 0    比无脑猜均值还差
# ============================================================
def accuracy(pred_val, true_val):
    ss_res = paddle.sum(paddle.square(pred_val - true_val))    # 模型的总平方误差
    ss_tot = paddle.sum(paddle.square(true_val - paddle.mean(true_val)))  # 猜均值的总平方误差
    if ss_tot.item() == 0:                                     # 标签毫无波动（极端情况）
        return 1.0 if ss_res.item() == 0 else 0.0              # 预测也对→1，否则→0
    else:
        r2 = 1.0 - ss_res / ss_tot                             # 核心公式
    return r2.item()                                           # 转成 Python 浮点数
```

### R² 的直觉：它是"和笨蛋基线比"的分数

$$R^2 = 1 - \frac{\text{模型的误差}}{\text{猜均值的误差}} = 1 - \frac{\text{MSE}}{\text{方差}}$$

分母是**最笨的预测器**——不管输入是什么，永远输出均值——的平方误差。所以 R² 回答的问题是：

> **"相比无脑猜均值，我的模型把误差消灭了百分之多少？"**

这个"自带基线"的设计是 R² 最大的优点。**0 分不等于"很差"，0 分精确地等于"和瞎猜一样"。** 而且它无量纲——分母分子的单位相同，一约就没了，所以不管标签是"环"还是"元"还是归一化后的 0~1，R² 说的话都一样。

### 实测：几个极端情况的 R²

R² **不是逐样本的分数**，它必须对一个"集合"计算。拿 5 条样本（真实年龄 10、12、9、15、8）当小数据集，试四种预测质量：

```text
【实测输出 · 手工小集合】
  true = [10. 12.  9. 15.  8.]，均值 = 10.8
  完美预测 pred=[10 12  9 15  8]  -> R² = 1.0000
  全猜均值 pred=[10.8 x5]         -> R² = 0.0000   ← 猜均值恰好得 0 分
  乱猜 5   pred=[5 x5]            -> R² = -5.4610  ← 比瞎猜差得多
  整体猜偏 +3                      -> R² = -0.4610  ← 方向对但整体偏高
  乱猜 20  pred=[20 x5]           -> R² = -13.7403 ← 差得离谱
```

把它画成"标尺"在脑子里过一遍：

```text
  R² 标尺
  -13.7        -5.5           0              0.54        1.0
    │           │             │               │           │
    ▼           ▼             ▼               ▼           ▼
  ┌───┬───────┬─────┬────────┬───────────────┬───────────┤
  │差到│乱猜个 │比瞎猜│  无脑   │   比瞎猜好    │  本模型的  │ 完美
  │离谱│离谱低 │差点  │  猜均值 │               │   成绩     │
  └───┴───────┴─────┴────────┴───────────────┴───────────┘
     负数区（比瞎猜还差）      基线      正数区（真学到了东西）
```

**三条关键读数：**

1. **猜均值恰好得 0 分。** 分母就是猜均值的误差，分子等于分母时 $1 - 1 = 0$。所以 R² 的"及格线"不是 0.6 也不是 0.5，而是 **0**——任何正数都意味着"至少比瞎猜强"。
2. **R² 可以是负数，而且不是 bug。** 预测离谱时，模型的误差比猜均值还大，$1 - \text{大于}1\text{的数}$ 就是负数。第 1 轮训练时模型还没学到东西，源码的日志里 `Train Acc=-5.0793`、`Test Acc=-0.2545`——**负数在训练初期是正常的**。
3. **R² 是"集合指标"，单条样本没有 R²。** 对单条样本，分母 $\sum(y-\bar y)^2 = 0$（只有一个数，它自己就是均值），公式直接除零。这就是源码里那个 `if ss_tot.item() == 0` 分支存在的原因——兜底返回 1.0（预测也对）或 0.0（预测错）。

> **Q：那 batch_size=64 时，batch 里 64 条标签恰好全部相同，是不是也会走 `ss_tot == 0` 分支？**
>
> **A：** 理论上是，实际上在这份数据里概率为零——836 条测试标签里有 27 种不同取值，64 条全同的概率是天文数字级的小。**但写这个分支不是多虑，是防御性编程的习惯**：万一有人拿这函数去处理"同一批次全是同一类别"的数据（比如按类别分桶训练），没有兜底就会除零崩溃。

### 实测：一个必须警惕的口径陷阱——逐 batch 平均 ≠ 整体

R² 必须对"你要报告的那个集合"一次算完。**把每个 batch 的 R² 算出来再平均，得到的是另一个数**，而且差得离谱：

```text
【实测输出 · 同一个 100 轮模型，同一份训练集，两种口径】
  整体一次算（3341 条合在一起）      R² = 0.5899
  53 个 batch 分别算再取平均        R² = 0.2898
  （53 个 batch 的 R²：最小 -1.1615，最大 0.8242）
```

为什么差这么多？因为**每个 batch 的分母是"batch 内部的方差"**：64 条样本的小集合，方差时大时小，小方差的 batch 分母小、R² 被压得很低甚至变负。**逐 batch 平均的 R² 没有清晰的含义，不能报。**

⚠️ 这意味着源码日志里有一个**口径不一致**的地方，必须看穿：

- `Train Acc`：53 个 batch 的 R² **平均**（batch 口径，第 100 轮 = 0.5763）；
- `Test Acc`：836 条测试集**整体**算的 R²（整体口径，第 100 轮 = 0.5383）。

**这两个数口径不同，不能直接比较！** 严谨比较要用整体口径算训练集（0.5899，1.15 节有实测）和测试集（0.5383）——按 R² 看，训练集确实略好于测试集，这才符合直觉。**答辩时如果老师问"你的 Train Acc 和 Test Acc 是同一个口径吗"，能答出这一条，就超过 90% 的初学者了。**

### 为什么还要看"四舍五入相等"这类硬标准

R² 好用，但它有个抽象的缺点：**0.5383 这个数不带单位**，答辩老师还是可能追问"到底差几环"。所以报成绩时最好搭配一个"说人话"的指标。同一份 100 轮模型的测试集预测：

```text
【实测输出 · 100 轮训练后的四种"成绩"】
  四舍五入后完全命中比例 = 0.2895
  R²（源码 accuracy）    = 0.5383
  |误差| <= 1 的比例      = 0.5251
  |误差| <= 2 的比例      = 0.7990
```

同一份预测，四种算法给出 **0.29 / 0.54 / 0.53 / 0.80** 四个数。

这就是为什么**"我的模型 0.5"这句话本身没有意义**——你必须说清"这个数是怎么算的"。

- `0.2895`（四舍五入恰好相等）：太严。预测 10.4、真实 10，算错，很反直觉。
- `0.5383`（R²）：**源码用的，也是回归任务的标准指标**，含义是"解释了 54% 的波动"。
- `0.5251`（误差 ≤1 环）：说人话版本——"一半的鲍鱼误差在 1 环以内"。
- `0.7990`（误差 ≤2 环）：用来展示"模型抓大方向还行，精度不够"。

## 1.15 训练循环：五步，仅此而已

神经网络训练的全部秘密，就在这五行：

```python
pred = model(batch_x)          # ① 前向：拿当前参数算一遍预测
loss = loss_fn(pred, batch_y)  # ② 算损失：衡量错了多少
loss.backward()                # ③ 反向：算出"每个参数该往哪调、调多少"（梯度）
optimizer.step()               # ④ 更新：按梯度微调所有参数
optimizer.clear_grad()         # ⑤ 清零：把梯度清空，为下一批做准备
```

**这五行就是深度学习的全部。** 所有的模型、所有的任务、所有的框架，本质都是这五步。

### 完整代码（带逐行注释）

```python
# ============================================================
# 模块 ⑥：训练循环 —— 100 个 epoch
# ------------------------------------------------------------
# 一个 epoch = 把所有训练数据完整过一遍 = 53 个 batch
# 每个 batch 走一遍"五步"
# 每个 epoch 结束后，在测试集上评估一次（不训练，只看成绩）
# ============================================================
num_epochs = 100

for epoch in range(num_epochs):
    model.train()                       # 切到"训练模式"（本模型无 Dropout，无实际影响，但必须写）
    epoch_loss = 0.0                    # 累加本轮所有 batch 的 loss
    epoch_acc  = 0.0                    # 累加本轮所有 batch 的 accuracy
    n_batches  = 0                      # 记一下本轮跑了多少个 batch（=53）

    for batch_x, batch_y in train_provider:          # 每轮自动重新洗牌（见 1.11 节）
        batch_x = paddle.to_tensor(batch_x.astype(np.float32))   # numpy → paddle 张量
        batch_y = paddle.to_tensor(batch_y.astype(np.float32))   # ⚠️ 必须转 float32

        pred = model(batch_x)                        # ① 前向
        loss = loss_fn(pred, batch_y)                # ② 损失

        loss.backward()                              # ③ 反向传播，梯度写进 param.grad
        optimizer.step()                             # ④ 用梯度更新参数
        optimizer.clear_grad()                       # ⑤ 清空梯度

        acc = accuracy(pred, batch_y)                 # 顺手算一下这批的 R²（注意：这是 batch 口径，见 1.14 节）
        epoch_loss += loss.item()                     # .item() 把单元素张量转成 Python 浮点数
        epoch_acc  += acc
        n_batches  += 1

    # ---------- 本轮训练结束，切到测试集评估 ----------
    model.eval()                                     # 切到"评估模式"
    with paddle.no_grad():                           # 不建计算图，省显存、提速
        test_pred = model(X_test)                    # 一次性把整个测试集喂进去（836 条，不大）
        test_loss = loss_fn(test_pred, Y_test).item()
        test_acc  = accuracy(test_pred, Y_test)

    if (epoch + 1) % 10 == 0 or epoch == 0:          # 第 1 轮 + 每 10 轮打印一次
        print(
            f"Epoch {epoch + 1:3d}/{num_epochs} | "
            f"Train Loss={epoch_loss / n_batches:.4f} "
            f"Train Acc={epoch_acc / n_batches:.4f} | "
            f"Test Loss={test_loss:.4f} "
            f"Test Acc={test_acc:.4f}"
        )
```

### 三个"开关"：`train()` / `eval()` / `no_grad()`

初学者经常搞不清这三者的区别。直接看实测：

```text
【实测输出 · 同一批数据，两种模式下的输出】
  train 模式输出 = [ 0.0009  0.0406  0.0011  0.0195 -0.0004]
  eval  模式输出 = [ 0.0009  0.0406  0.0011  0.0195 -0.0004]
  是否相同 = True （因为网络里没有 Dropout / BatchNorm）
```

**在这个模型上，`train()` 和 `eval()` 的输出完全一样**——因为网络里只有 `Linear` 和 `ReLU`，它们的行为不随模式改变。

那为什么还要写？因为**一旦你以后加了 `Dropout`（训练时随机丢弃一部分神经元）或 `BatchNorm`（用批次统计量做归一化），这两行就变成生死攸关的**：

| 层类型 | `train()` 时 | `eval()` 时 |
|---|---|---|
| `Dropout` | 随机把一部分输出置 0 | 全部保留 |
| `BatchNorm` | 用当前 batch 的均值和方差 | 用训练时累积的滑动平均 |
| `Linear` / `ReLU` | 一样 | 一样 |

**如果忘了在评估前调 `eval()`**，Dropout 还在随机丢，你的测试成绩会明显偏低，而且每次都不一样——你会以为模型不稳定。

`no_grad()` 则是另一回事：

- 它**不改变数值**，只改变"要不要记录计算图"。
- 训练时需要计算图（为了反向传播），所以不能加。
- 评估时不需要，加上它可以**省显存、提速**。

> **Q：为什么评估要 `with paddle.no_grad():`，但训练时不加？**
>
> **A：** 因为反向传播需要"记住前向过程中每一步的中间结果"（这样才能用链式法则算梯度）。这些中间结果就是"计算图"，很占显存。
>
> 评估时不打算更新参数，所以不需要计算图，用 `no_grad()` 告诉框架"别记了"。
>
> 如果不加会怎样？**结果一样，只是慢一点、占显存多一点。** 在这个小模型上看不出差别，但在大模型（比如 ResNet）上，不加 `no_grad()` 很可能直接显存溢出（OOM）。

### ⑤ 清零这一步，忘了会怎样

这是最容易漏的一步，后果也很直观：**梯度会累加。**

```python
import paddle
import paddle.nn as nn
import numpy as np

lin = nn.Linear(8, 1)
xx = paddle.randn([8, 8])
yy = paddle.randn([8, 1])
lf = nn.MSELoss()

l1 = lf(lin(xx), yy)
l1.backward()
g1 = lin.weight.grad.numpy().ravel()[:3].copy()      # 记下第一次的梯度

l2 = lf(lin(xx), yy)
l2.backward()                                        # ⚠️ 故意不清梯度
g2 = lin.weight.grad.numpy().ravel()[:3].copy()

print('第 1 次反传后 grad 前 3 个 =', np.round(g1, 6))
print('第 2 次反传后 grad 前 3 个 =', np.round(g2, 6))
print('是否恰好变成 2 倍 =', np.allclose(g2, 2 * g1, atol=1e-6))
```

**【实测输出】**
```text
第 1 次反传后 grad 前 3 个 = [-5.73804   3.747469  4.125636]
第 2 次反传后 grad 前 3 个 = [-11.476079   7.494938   8.251272]
是否恰好变成 2 倍 = True
```

（具体数值取决于权重随机初始化和输入数据，你跑出来的数会不一样。但"**第二次恰好是第一次的 2 倍**"这个结论永远成立。）

**第二次的梯度是第一次的两倍。** 因为 `backward()` 是**累加**到 `.grad` 上的，不是覆盖。

如果忘了 `clear_grad()`，那么第 $k$ 批的梯度会变成前 $k$ 批的**总和**，越往后越大，参数一步迈得越来越远，最后直接发散（loss 变成 `nan`）。

> **Q：那反过来，`clear_grad()` 放在 `backward()` 前面行不行？**
>
> **A：** 行，而且有些人就这么写。顺序是：
>
> ```python
> optimizer.clear_grad()      # 先清
> pred = model(batch_x)
> loss = loss_fn(pred, batch_y)
> loss.backward()             # 再算
> optimizer.step()            # 再更新
> ```
>
> 这和源码的顺序（先 backward → step → clear）在数学上完全等价，因为"清"发生在两个 batch 之间就行，具体在哪个位置无所谓。
>
> **但有一个必须遵守的铁律：`clear_grad()` 必须在 `backward()` 之后、下一个 `backward()` 之前。** 绝对不能写成 `backward() → clear_grad() → step()`——那样 `step()` 拿到的梯度全是 0，参数一步都不动，你会看到 loss 完全不变。

### 一个真实存在的 API 陷阱

清梯度这件事，**优化器和层，用的是两个不同名字的方法**：

```text
【实测输出】
  optimizer.clear_grad() 后 grad 前 3 个 = [0. 0. 0.]
  （层自己也有 clear_gradients()，但没有 clear_grad）
  lin.clear_grad() -> AttributeError: 'Linear' object has no attribute 'clear_grad'
```

- `optimizer.clear_grad()` —— 优化器的，**没有 s**
- `layer.clear_gradients()` —— 层的，**有 s**

写错就是 `AttributeError`。这个坑我实测时自己也踩了一次。**记法：优化器管的是"grad"，层管的是"gradients"，各按各的来。**

### 实测：种子固定后，结果完全可复现


### 一个必须解释的怪现象：Train Loss 比 Test Loss 还大

细看第 100 轮：`Train Loss=4.5587`，`Test Loss=3.3409`。

**训练集上的误差，竟然比测试集还大？** 这不是应该反过来吗（训练集表现好、测试集表现差）？

第一反应可能是："训练时的 loss 是 53 个 batch 的平均，其中包括了本轮刚开始时那些'还没更新好'的参数算出来的 loss，所以偏大。"

**这个解释听着很合理——但是错的。** 我实测验证过：

```text
【实测输出 · 训练结束后，在训练集上"一次性"算 MSE 和 R²】
  训练集整体 MSE（训练结束后一次算完） = 4.5631
  测试集整体 MSE                      = 3.3409
  训练集整体 R² = 0.5899
  测试集整体 R² = 0.5383
```

**用最终参数在训练集上一次性算，MSE 还是 4.5631，确实比测试集的 3.3409 高。** 所以"滑动平均"不是原因。

（顺便说：4.5631 和训练时打印的 4.5587 极其接近，只差 0.0044——这恰好说明"53 个 batch 的滑动平均"是对整轮 MSE 的一个**非常好的近似**。这个近似成立，是因为每个 batch 只有 64 条，参数更新幅度很小。）

**真正的原因在数据里：**

```text
【实测输出 · 训练集与测试集的"难度"】
  训练集 环数: 均值=10.040 方差=11.126 最小=1 最大=29
  测试集 环数: 均值=9.508 方差=7.236 最小=3 最大=21
  训练集 MSE=4.5631 -> R² = 1 - 4.5631/11.1262 = 0.5899
  测试集 MSE=3.3409 -> R² = 1 - 3.3409/7.2356 = 0.5383
```

**测试集比训练集"简单"**：它的环数方差只有 7.236，而训练集是 11.126。测试集里最老的鲍鱼只有 21 环，训练集里有 29 环的。

对于 MSE 这种指标，**"样本本身差异小" = "更容易预测得准"**。如果你永远猜 9.5，在一个方差 7.2 的集合上误差就比在方差 11.1 的集合上小。

所以要**用 $R^2$（决定系数）来公平比较**：

$$R^2 = 1 - \frac{\text{MSE}}{\text{方差}}$$

- 训练集 $R^2 = 0.5899$
- 测试集 $R^2 = 0.5383$

**按 $R^2$ 看，测试集确实比训练集差一点（0.538 < 0.590）。** 这才是符合直觉的结论。

> 好消息是：**新版源码的 `accuracy` 本身就是 R²**（1.14 节讲过），所以你不需要手工换算——只要拿最终模型在两个集合上**整体**各调一次 `accuracy`，打印出来的就是这两个数。唯一要注意的是**别拿日志里的 Train Acc（batch 平均口径，0.5763）去和 Test Acc（整体口径，0.5383）直接比**，它们口径不同；公平的比较就是上面这两行 0.5899 vs 0.5383。

> **Q：那为什么测试集方差会比训练集小？是巧合吗？**
>
> **A：** 不是巧合，是**顺序切分**造成的必然结果。
>
> 源码的切分方式是 `raw_data[:offset]` / `raw_data[offset:]`——**取前 80% 当训练集，后 20% 当测试集**，中间没有任何打乱。
>
> 而这份数据文件并不是随机排列的：实测显示数据的组织方式会让"靠后的部分"整体偏小、偏"温和"。于是测试集恰好成了一个"简单样本集合"。
>
> 这是**数据切分的一个真实风险**：如果原始数据有隐含顺序（按时间、按批次、按类别），顺序切分会让训练集和测试集的分布不一致。
>
> 那要不要改成随机切分？1.17 节有实测对比——结论有点出人意料。

### 为什么小模型上 GPU 反而慢

GPU 快到离谱的前提是"**一次要算的计算量足够大**"。它的优势来自"几千个核心同时开工"。

但这个模型的一批数据是 `64 × 8`，第一层是 `(64,8) @ (8,128)`，一共 64×8×128 = 65536 次乘加。**这个量对 GPU 来说太小了**——小到"启动一次 GPU 计算"的开销就超过了计算本身。

更具体的开销有两个：

1. **数据搬运（H2D）。** 每一批都要把 numpy 数组拷到显存里。实测这个开销很显著：

```text
【实测输出 · 搬运开销】
  CPU: 2000 次 to_tensor 建张量 = 0.0241 秒
  GPU: 2000 次 to_tensor + 前向 = 0.3836 秒
```

同样的 2000 次操作，CPU 用 0.0241 秒，GPU 用 0.3836 秒——**慢了 16 倍**。因为每次 `to_tensor` 都要过一遍 PCIe 总线。

2. **核函数启动（kernel launch）。** 每个算子（加法、矩阵乘、ReLU）都是一次独立的 GPU 调用，每次有几微秒的固定开销。一轮有 53 批 × 十几个算子，累积起来就不可忽略了。

### 什么时候 GPU 才真的快

看第二、三行：**把 batch 从 64 改成 3341（全量一批），GPU 立刻快 10 倍；再把模型放大到 512-256-128，GPU 快 94 倍。**

规律很清楚：

```text
单个矩阵乘法的规模越大  →  GPU 优势越明显
batch_size 越大         →  GPU 优势越明显
模型越宽越深            →  GPU 优势越明显
```

所以题目那句"3060 及以上必须部署 GPU 版，速度提升 40 倍"，**指的是后面那些真正大的任务**（图像分类、目标检测、大语言模型），而不是这道只有 1 万多个参数的小题。

> **Q：那这道题我还要不要配 CUDA？**
>
> **A：** **要，因为题目第 6 条是硬要求。** 而且你要在作业里给出 `paddle.get_device()` 的输出作为证据。
>
> 但同时**你要能解释清楚这张表**。答辩时如果老师问"为什么你的 GPU 只用了不到 5 秒，而别人说 GPU 快 40 倍"，你可以这样答：
>
> > "因为这个模型很小（11521 个参数）、每批只有 64×8 的数据，单次计算量不足以摊薄显存搬运和核函数启动的固定开销。我实测过：同一模型下 CPU 反而快 2.25 倍；但把 batch 提到全量、把网络加宽到 512-256-128 后，GPU 快了 94 倍。所以 'GPU 快 40 倍' 有前提条件，本题属于 GPU 不占优的小规模场景。"
>
> **这段话的分量，比"我跑通了"高得多。** 它证明你不是照着抄，而是真的观察了。

> **Q：`paddle.set_device("gpu:0")` 里的 `0` 是什么意思？我有两块卡怎么办？**
>
> **A：** `"gpu:0"` 是"第 0 块 GPU"。`"gpu:1"` 是第二块。用 `paddle.device.cuda.device_count()` 看有几块。
>
> 多卡训练（数据并行）要用 `paddle.distributed`，属于进阶内容，本题用不到。

**【动手】**
1. 跑 `nvidia-smi`，把你显卡的型号、显存、CUDA Version 记下来。
2. 在代码里把 `paddle.set_device("gpu:0")` 改成 `"cpu"`，跑 100 轮，用 `time.time()` 记下耗时，和 GPU 版对比。**（小模型上你大概率会发现 CPU 更快，别怀疑自己。）**
3. 把 `batch_size` 改成 3341（全量），再对比一次。

## 1.17 参数实验：把"玄学调参"变成"可测量的对照"

这一节全部是**对照实验**。每一行只改一个参数，其他完全不动（种子固定）。

### 实验一：学习率

学习率（`learning_rate`）是**最重要的一个超参数**。它决定"每次沿梯度方向迈多大一步"。

```text
【实测输出 · 学习率扫描（20 轮，其余默认）】
  lr=0.1      ep1:L28.98 | ep5:L5.94 | ep20:L5.42  -> 末轮 TestA=0.3904
  lr=0.01     ep1:L18.80 | ep5:L5.70 | ep20:L5.27  -> 末轮 TestA=0.4800
  lr=0.001    ep1:L64.72 | ep5:L6.91 | ep20:L4.97  -> 末轮 TestA=0.4863
  lr=0.0001   ep1:L108.97 | ep5:L48.63 | ep20:L7.46  -> 末轮 TestA=0.2208
  lr=1e-05    ep1:L111.27 | ep5:L108.79 | ep20:L95.20  -> 末轮 TestA=-10.2560
```

（`L` = Train Loss，`TestA` = Test Acc（测试集整体 R²）。）

**逐行读：**

| 学习率 | 第 1 轮 loss | 第 20 轮 loss | 判断 |
|---|---|---|---|
| 0.1 | 28.98 | 5.42 | 起步快，但最终不如 0.001 |
| 0.01 | 18.80 | 5.27 | 快且稳 |
| **0.001（源码）** | 64.72 | **4.97** | 起步慢，**最终最好** |
| 0.0001 | 108.97 | 7.46 | 太慢，20 轮远远不够 |
| 0.00001 | 111.27 | **95.20** | **几乎没学动**，R² 是 -10.3（比瞎猜差 10 倍） |

**这张表最有说服力的地方是最后一行**：`lr=1e-5` 时，第 1 轮 loss 是 111.27，第 20 轮是 95.20——**20 轮只降了 16**，R² 还是 -10.26：模型的预测离谱到远超"猜均值"的水平，R² 用负数直接把它钉在耻辱柱上。（顺便体会 R² 的好处：负数**自带判断**，一眼看出"没学到东西"，不需要像 loss 那样知道基线才能解读。）

而 `lr=0.001` 时，第 20 轮已经到 4.97。

> **Q：为什么 `lr=0.1` 起步最快（第 1 轮就 28.98），最后反而不如 `lr=0.001`？**
>
> **A：** 这就是"步子太大"的典型症状。
>
> 大步长在离最优点远的时候很爽，一下就跨过去了；但接近最优点时，大步长会**反复越过**最低点，在附近来回震荡，收敛不到精确的位置。
>
> 反过来 `lr=0.001` 起步慢（第 1 轮 64.72，因为从随机初始化的位置到"大概对"要走很多小步），但每一步都稳，最终能落到更低的地方。
>
> 这也解释了为什么实际训练常用"**学习率衰减**"：前期大步快跑，后期小步微调。源码没有做衰减，是个可以改进的点。

> **Q：那 `lr=1e-5` 为什么"几乎没学动"？是不是程序坏了？**
>
> **A：** 不是坏了，是**步长小到 20 轮根本走不完**。
>
> 从 loss 111 到 loss 5，需要走很长一段路。每步只迈 1e-5，就像用蚂蚁搬山。实测它 20 轮只从 111 降到 95，再给 200 轮可能会降下来，但没必要——直接把学习率调大就行。
>
> **诊断经验**：如果 loss 几乎不降（比如 20 轮降不到 20%），先怀疑**学习率太小**；如果 loss 变成 `nan` 或剧烈跳动，先怀疑**学习率太大**。

### 实验二：批大小（batch_size）

```text
【实测输出 · batch_size 对照（20 轮）】
  bs=16    -> TrainL=4.9627 TestL=4.6345 TestA=0.3595
  bs=64    -> TrainL=4.9673 TestL=3.7168 TestA=0.4863
  bs=256   -> TrainL=6.5115 TestL=5.0353 TestA=0.3041
  bs=3341  -> TrainL=86.6709 TestL=71.7473 TestA=-8.9159
```

| batch_size | 一轮更新次数 | 第 20 轮 TestA | 说明 |
|---|---|---|---|
| 16 | 209 | 0.3595 | 更新多但梯度太吵 |
| **64（源码）** | **53** | **0.4863** | **最好** |
| 256 | 14 | 0.3041 | 更新太少，20 轮不够 |
| 3341 | 1 | -8.9159 | 20 轮只更新 20 次，等于没训 |

**`bs=3341` 那一行特别值得看**：Train Loss 还是 86.67，R² 是 -8.92——预测离均值远到"比瞎猜差 9 倍"。因为一轮只有 1 次更新，20 轮总共 20 次更新——**这个模型的参数几乎还在初始化的原地**。

> **Q：为什么 `bs=16` 反而不如 `bs=64`？不是"更新次数越多越好"吗？**
>
> **A：** 更新次数多确实是好事，但 `bs=16` 的每批只有 16 条样本，**梯度噪声太大**。想象一下：你用 16 个人的身高去估计全国平均身高，误差肯定比用 64 个人大。
>
> 噪声大的梯度会让参数"来回摆"，虽然长期看方向是对的，但短期内效率不高。
>
> `batch_size` 的选择本质是**在"更新频率"和"梯度质量"之间找平衡**：
> - 小 batch：更新多、噪声大、可能跳出坏的局部最优。
> - 大 batch：更新少、梯度准、容易卡住。
>
> 64 左右在中小数据集上是个很稳的默认值。

### 实验三：有没有 ReLU

```text
【实测输出 · 有/无激活函数（20 轮）】
  有 ReLU : TrainL=4.9673 TrainA=0.5313 TestL=3.7168 TestA=0.4863
  无 ReLU : TrainL=5.3538 TrainA=0.4944 TestL=3.9685 TestA=0.4515
```

去掉 ReLU 之后，成绩确实变差了一点（0.4863 → 0.4515），但**没有崩**。

> **Q：为什么去掉激活函数没有"崩掉"？我记得老师说没有激活函数，多层网络等于一层？**
>
> **A：** 老师说的是对的——**理论上**，四个线性层串起来等价于一个线性层：
>
> $$W_4(W_3(W_2(W_1 x))) = (W_4W_3W_2W_1)x = Wx$$
>
> 所以"无 ReLU 版"实际上就是一个**线性回归**。它当然能学——线性回归也是能预测的，只是表达能力弱，拟合不了非线性的关系。
>
> 实测的 0.4515 vs 0.4863 差距不大，恰好说明**这份数据的规律本身比较接近线性**（毕竟"越重越大→环数越多"基本是单调关系）。
>
> 但**理论上等价不等于实测完全一样**：`5.3538` 比 `4.9673` 差一点，是因为四层线性堆叠让优化变难了（连乘导致梯度的尺度不稳定）。**一个参数都没省，还更难训**——这就是为什么"堆线性层"是纯亏本买卖。
>
> 更狠的验证：如果把 4 层换成 1 层 `Linear(8,1)`，理论上应该和无 ReLU 版**完全等价**。你可以自己试试。

### 实验四：性别编码（单列 vs 独热）

这是本章唯一一个"**概念上重要、数值上不明显**"的实验。

```text
【实测输出 · sex 编码对照（20 轮）】
  独热后特征维度 = 10 （原 8）| 首行前 4 列 = [1.         0.         0.         0.51351351]
  单列编码(源码) : TrainL=4.9673 TestL=3.7168 TestA=0.4863
  三列独热       : TrainL=4.9777 TestL=3.6359 TestA=0.4975
```

**独热编码（one-hot）** 的做法是：把 `sex` 一列换成三列——

| 原始 | M 列 | F 列 | I 列 |
|---|---|---|---|
| M | 1 | 0 | 0 |
| F | 0 | 1 | 0 |
| I | 0 | 0 | 1 |

这样三个类别之间**没有任何虚假的大小关系**。特征维度从 8 变成 10。

**结果：TestA 从 0.4863 提升到 0.4975。**

> **Q：提升了 0.0112，这算"显著提升"吗？我该不该改成独热？**
>
> **A：** **单看这一次实验，不能说显著。**
>
> 理由：20 轮的测试 R² 本身就在 0.39~0.54 之间波动（看 1.15 节那张 100 轮的表，第 30 轮 0.3860、第 70 轮 0.5377）。0.0112 的差距**完全落在噪声范围内**。
>
> 要证明"独热更好"，你需要：
> 1. 固定种子，跑 5 个不同的种子，取平均值和标准差；
> 2. 或者跑更多轮数让模型收敛。
>
> **但概念上，独热是对的**——它避免了"把类别当连续量"的错误。这是**原则问题，不是分数问题**。
>
> 所以我的建议是：**作业里用哪一种都可以，但要在报告里写清楚"我知道独热在概念上更正确，实测差异在噪声范围内"。** 这句话会让老师看到你的严谨。

### 实验五：顺序切分 vs 随机切分

1.15 节留了个悬念：顺序切分让测试集"变简单"了，那换成随机切分会怎样？

```text
【实测输出 · 切分方式对照（20 轮）】
  顺序切分(源码): 训练环数均值=10.040 测试环数均值=9.508 -> TestA(R²)=0.4863
  随机切分      : 训练环数均值=9.964 测试环数均值=9.813 -> TestA(R²)=0.5237
```

| 切分方式 | 训练集均值 | 测试集均值 | 差距 | TestA（R²） |
|---|---|---|---|---|
| 顺序（源码） | 10.040 | 9.508 | 0.532 | 0.4863 |
| 随机 | 9.964 | 9.813 | **0.151** | **0.5237** |

**随机切分让两个集合的均值接近多了**（差 0.151 vs 差 0.532），分布更一致——这符合我们的预期。而且 R² 口径下，随机切分的成绩**反而更好**（0.5237 > 0.4863）。

> **Q：不是说顺序切分的测试集"偏简单"、成绩会虚高吗？怎么到了 R² 这里，随机切分反而赢了？**
>
> **A：** 这正是 R² 设计得巧妙的地方——**它把"测试集偏简单"带来的便宜自动扣回去了**。
>
> 回忆 1.15 节：顺序切分的测试集方差只有 7.236（训练集 11.126），样本本身差异小，MSE 天然就低。如果用 MSE 报成绩，顺序切分会"白赚"这部分便宜——这正是 1.15 节那个"Train Loss 比 Test Loss 还大"怪现象的来源。
>
> 但 R² 的分母恰好就是**这个集合自己的方差**：测试集"简单"（方差小）→ 分母小 → 打分标准自动变严。**两个效应互相抵消，剩下的就是模型真实的本事。**
>
> 所以在 R² 口径下：顺序切分 0.4863、随机切分 0.5237——随机切分不仅分布更合理，成绩还更高。**0.5237 才是这个模型在这份数据上的真实水平。**
>
> 这引出一个很重要的实验纪律：**报告成绩时，必须说清切分方式和指标口径。** 同一个模型，换个切分方式，MSE 口径下能从 3.72 变成 4.63；换个指标口径，"谁好谁坏"的结论都可能反转。**只报对自己最有利的那个组合，就是在误导。**
>
> **工程上的正确做法**：随机切分（或分层抽样）+ R² 报成绩，并且固定随机种子，让结果可复现。

### 实验六：训练轮数

```text
【实测输出 · 轮数影响（同一随机种子）】
  Epoch  50 | 训练集整体 MSE=4.6609 R²=0.5811 | 测试集 MSE=3.6638 R²=0.4936
  Epoch 100 | 训练集整体 MSE=4.5631 R²=0.5899 | 测试集 MSE=3.3409 R²=0.5383
  Epoch 150 | 训练集整体 MSE=4.4707 R²=0.5982 | 测试集 MSE=3.6917 R²=0.4898
  Epoch 200 | 训练集整体 MSE=4.6240 R²=0.5844 | 测试集 MSE=3.1999 R²=0.5577
  Epoch 250 | 训练集整体 MSE=4.3425 R²=0.6097 | 测试集 MSE=3.2693 R²=0.5482
  Epoch 300 | 训练集整体 MSE=4.4160 R²=0.6031 | 测试集 MSE=3.2155 R²=0.5556
```

**这张表特别诚实，因为它不好看：**

- 测试集 R² 在 0.4898 ~ 0.5577 之间**来回跳**，没有单调上升。
- 训练集 MSE 从 4.66 缓慢降到 4.42（R² 从 0.58 缓慢爬到 0.60），**降幅很小**。

**没有出现明显的过拟合**（训练 MSE 一直高于测试 MSE，且持续缓慢下降），但也**没有明显变好**。

> **Q：既然 100 轮和 300 轮差不多，源码为什么设 100？**
>
> **A：** 因为 100 轮已经进入平台期了，再训只是浪费时间（虽然只要 5 秒）。
>
> 更重要的判断依据是**学习曲线**：如果测试指标在连续 20~30 轮里都没有创新高，就说明该停了（这叫**早停 early stopping**）。
>
> 这里还有个客观限制：**这个任务本身的可预测性有限**。鲍鱼的环数受很多因素影响（年龄、生长环境、食物），8 个体型特征最多只能解释一部分方差。$R^2 \approx 0.54$ 说明"解释了一半多一点的波动"，剩下的解释不了。
>
> **这时候继续调网络是没用的**——需要更多特征，或者换问题。**能识别出"这里已经到瓶颈了"，比盲目调参更重要。**

### 六个实验的总表

| 变量 | 源码取值 | 更好的选择？ | 实测依据 |
|---|---|---|---|
| 学习率 | 1e-3 | 1e-2 或 1e-3 | 1e-5 完全学不动，1e-1 后期震荡 |
| batch_size | 64 | 64 | 16 噪声大，3341 轮次太少 |
| 激活函数 | ReLU | 必须有 | 去掉后略差且无收益 |
| sex 编码 | 单列 1/-1/0 | 独热（概念更正确） | 差异在噪声内 |
| 切分方式 | 顺序 8:2 | 随机 8:2 | R² 口径下随机切分更好（0.5237 vs 0.4863） |
| 轮数 | 100 | 100~200 + 早停 | 100 轮后收益极小 |

选**一个**变量，用固定种子跑 3 组对照，做成和你上面看到的一样的表。**记住：只改一个变量。** 改了学习率又改了 batch，你就永远说不清是谁的功劳。

## 1.18 保存与推理：让模型"活"到下一次

训练完了，参数在内存里。程序一关，全没了。所以要存下来。

### 存进去的到底是什么

```text
【实测输出 · abalone_model.pdparams 里有什么】
  类型 = dict | 键数 = 8
   net.0.weight shape=(8, 128) dtype=paddle.float32
   net.0.bias   shape=(128,) dtype=paddle.float32
   net.2.weight shape=(128, 64) dtype=paddle.float32
   net.2.bias   shape=(64,) dtype=paddle.float32
   net.4.weight shape=(64, 32) dtype=paddle.float32
   net.4.bias   shape=(32,) dtype=paddle.float32
   net.6.weight shape=(32, 1) dtype=paddle.float32
   net.6.bias   shape=(1,) dtype=paddle.float32
```

**8 个键 = 4 个 Linear × (weight + bias)。** 编号 `0/2/4/6` 对应 `Sequential` 里的第 0、2、4、6 项——正是那 4 个 `Linear`（`1/3/5` 是 ReLU，没有参数）。

形状全部对得上 1.13 节的参数表。文件大小 46751 字节 ≈ 11521 个 float32（每个 4 字节 = 46084 字节）+ 一点头部信息。

> **Q：`state_dict` 和 `model` 有什么区别？为什么不直接 `paddle.save(model)`？**
>
> **A：** `state_dict()` 只导出**参数**（一堆张量），不导出**代码**（类的定义）。
>
> 这是个优点：
> - **文件小、干净。** 就是一堆数字。
> - **和代码解耦。** 你可以改 `MLP` 的 `forward` 逻辑（比如加个打印），只要层的名字和形状不变，旧参数照样能load。
> - **安全。** 不用反序列化任意 Python 对象。
>
> 代价是：**加载时必须先有 `MLP` 这个类的定义**。所以推理那一段要先 `MLP(8)` 建个空网络，再 `set_dict` 把参数填进去。

### 保存

```python
paddle.save(model.state_dict(), "abalone_model.pdparams")
```

一行，没有坑。

### 推理：源码那 12 行，逐行讲

```python
# ============================================================
# 模块 ⑦：推理 —— 从测试集随机抽 1 条，预测它的年龄
# ------------------------------------------------------------
# 关键点：新建一个"同结构"的网络，把保存的参数塞进去
#        然后一次只喂 1 条数据（所以要做 reshape(1, -1)）
# ============================================================
infer_model = MLP(input_dim=train_data[:, :-1].shape[1])   # 建同结构空网络（参数是随机的）
infer_model.set_dict(paddle.load("abalone_model.pdparams"))  # 用保存的参数覆盖随机值
infer_model.eval()                                          # 切评估模式

idx = np.random.randint(0, len(test_data))                  # 随机抽一个下标
single_x = paddle.to_tensor(
    test_data[idx, :-1].reshape(1, -1).astype(np.float32)   # 取 8 个特征，变成 (1, 8)
)
true_age = test_data[idx, -1]                               # 这一条的真实环数
print(f"选取的数据: {single_x}")
print(f"真实年龄: {true_age}")

with paddle.no_grad():                                      # 推理不需要计算图
    pred_age = infer_model(single_x).item()                 # .item() 取出那个标量

print(f"预测年龄: {pred_age:.2f} (保留两位小数)")
```

### 三个细节

**细节 1：为什么要 `reshape(1, -1)`？**

`test_data[idx, :-1]` 的形状是 `(8,)`，是一维的。网络要的是 `(batch, 8)`，也就是 `(1, 8)`。

`reshape(1, -1)` 的意思是："**变成 1 行，列数你自动算**"。因为总共 8 个数，所以自动算成 `(1, 8)`。

> **Q：如果忘了 `reshape`，直接喂 `(8,)` 会怎样？**
>
> **A：** 会报形状不匹配的错。因为 `Linear(8, 128)` 要的是 `(batch, 8)`，你给 `(8,)` 它不知道该把哪一维当成"8 个特征"。
>
> `-1` 的作用是"这一维你自己推"。它只能出现一次，否则 numpy 就不知道该怎么推了。

**细节 2：为什么用 `astype(np.float32)`？**

因为 `test_data` 是 `float64`（还记得吗？`load_data` 返回的就是 `float64`），而模型参数是 `float32`。

**mixed dtype 会报错**，或者更糟——自动转换后性能变差。所以统一转成 `float32`。

> **Q：为什么模型默认用 `float32` 而不是 `float64`？精度不是越高越好吗？**
>
> **A：** 因为**显存和速度**。
>
> - `float32` 占 4 字节，`float64` 占 8 字节——**显存直接翻倍**。
> - GPU 的浮点运算单元对 `float32` 的吞吐量通常是 `float64` 的 2 倍以上（消费级显卡甚至是 32 倍）。
> - 神经网络的训练本身就有大量噪声（随机初始化、随机洗牌、mini-batch），`float64` 那点额外精度**根本用不上**。
>
> 所以深度学习的默认精度就是 `float32`。只有在做科学计算（比如求解微分方程）时才用 `float64`。

**细节 3：`np.random.randint(0, len(test_data))` 会不会越界？**

这个问题我一开始怀疑源码有 bug——因为标准库的 `random.randint(a, b)` **是闭区间**（含 b），如果照搬就会取到 `len(test_data)`，越界。

但 `np.random.randint` **的上界是开区间**。实测：

```text
【实测输出 · 两种 randint 的边界】
np.random.randint(0,5) 出现过的值 = [0, 1, 2, 3, 4]
random.randint(0,5) 出现过的值 = [0, 1, 2, 3, 4, 5]
np.random.randint(0,836) 最大值 = 835
```

**`np.random.randint(0, 836)` 的最大值就是 835，永远不会返回 836。** 所以源码**没有越界 bug**。

（我抽了 20 万次验证：落在下标 836 的次数 = 0。）

> **Q：那如果我手滑写成了标准库的 `random.randint` 呢？**
>
> **A：** 那就真的会越界。实测用 `idx = 836` 去索引：
>
> ```text
> 【实测输出】
> 真的用 idx=836 去索引 -> IndexError: index 836 is out of bounds for axis 0 with size 836
> ```
>
> 而且这个 bug **极难复现**——836 分之一的概率，你可能跑 100 次都没事，答辩现场一跑就崩了。
>
> **这就是"边界条件"的可怕之处：它能让你在最重要的时候失败。**
>
> 稳妥写法：`idx = np.random.randint(0, len(test_data))` 是对的，但**更好的是加一行断言**：
>
> ```python
> idx = np.random.randint(0, len(test_data))
> assert 0 <= idx < len(test_data), f'下标越界: {idx}'
> ```

```text
【实测输出 · 往返一致性】
  两次加载结果是否完全相同 = True
  三行预测值 = [11.6213  8.5051  9.8089] | 真实 = [12. 14. 13.]
```

**两次独立加载，输出逐位相同。** 说明 `save`/`load` 没有丢信息。

顺便看这三条的具体误差：`11.62 vs 12`（差 0.38，很好）、`8.51 vs 14`（差 5.49，很差）、`9.81 vs 13`（差 3.19，偏差大）。

> **Q：为什么第二条差这么多？这模型是不是有问题？**
>
> **A：** 不是模型坏了，是**这个任务的难度决定的**。
>
> 8 个体型特征无法区分"14 环的鲍鱼"和"9 环的鲍鱼"——如果它们体型相似，模型只能给出"平均水平"的预测。
>
> 看整体统计就明白了：
>
> ```text
> 【实测输出 · 836 条测试样本的整体表现】
>   预测 均值=9.630 标准差=2.240 最小=3.413 最大=17.731
>   真实 均值=9.508 标准差=2.690 最小=3.000 最大=21.000
>   相关系数 = 0.7408
>   平均绝对误差 MAE = 1.3121
>   |误差| <= 1 的比例 = 0.5251
>   |误差| <= 2 的比例 = 0.799
> ```
>
> **关键看"标准差"**：真实值的标准差是 2.690，预测值的标准差只有 2.240。
>
> 这说明模型的预测**"向均值收缩"**了——它不敢预测 21，也不敢预测 3，都往 9.5 附近靠。这是 MSE 损失函数的天然倾向：**预测极值风险大（错了罚得重），预测均值最安全。**
>
> 相关系数 0.7408 说明"趋势是对的"，MAE 1.31 说明"平均差 1.3 个环"。**这是一个"能看出趋势、但精度有限"的模型。** 老实写进报告，比吹成 0.9 准确率可信得多。

### 完整代码

```python
"""
闯关10 + 闯关11：鲍鱼年龄预测
------------------------------------------------------------
数据集：10abalone.data  4177 行 × 9 列
        前 8 列 = 性别/长度/直径/高度/总重量/皮重/内脏重量/克重
        第 9 列 = 环数（题目称"年龄"）
任务：用 4 层全连接网络（8→128→64→32→1）预测环数
运行：python 10-11鲍鱼年龄预测.py
"""

import csv
import os

import numpy as np
import paddle
import paddle.nn as nn

# ---------- 全局配置 ----------
DATA_FILE = '10abalone.data'      # 数据文件名，只在这里出现一次
MODEL_FILE = 'abalone_model.pdparams'
NUM_EPOCHS = 100
BATCH_SIZE = 64
LEARNING_RATE = 1e-3
SEED = 2026                        # 固定随机种子 → 结果可复现


# ============================================================
# 模块 ①：加载数据 —— 文本 → (4177, 9) 的 float64 矩阵
# ============================================================
def load_data(file_path=DATA_FILE):
    """逐行读取 CSV，把性别映射成数字，拼成 numpy 二维数组。

    第 0 列：M→1.0  F→-1.0  I→0.0
    第 1~7 列：长度/直径/高度/总重量/皮重/内脏重量/克重
    第 8 列：环数（标签）
    """
    data = []
    skipped = 0                                     # 记录跳过了多少非法行

    with open(file_path, 'r', encoding='utf-8') as f:
        for line_no, row in enumerate(csv.reader(f), start=1):
            if not row:                             # 空行
                continue

            sex = row[0]
            if sex == 'M':
                sex_val = 1.
            elif sex == 'F':
                sex_val = -1.
            elif sex == 'I':
                sex_val = 0.
            else:
                # 原版是 break（静默丢弃后面所有行），这里改成 continue + 报警
                print(f'[警告] 第 {line_no} 行首列不是 M/F/I：{row[0]!r}，已跳过')
                skipped += 1
                continue

            try:
                num_vals = [float(x) for x in row[1:]]
            except ValueError as e:
                print(f'[警告] 第 {line_no} 行有非法数值，已跳过：{e}')
                skipped += 1
                continue

            if len(num_vals) != 8:                  # 少一列或多一列
                print(f'[警告] 第 {line_no} 行有 {len(num_vals)} 个数值（应为 8），已跳过')
                skipped += 1
                continue

            data.append([sex_val] + num_vals)

    arr = np.array(data)
    # 三道保险：早失败，胜过训练完 100 轮才发现数据错了
    assert arr.ndim == 2, f'读出来不是二维数组，shape={arr.shape}'
    assert arr.shape[1] == 9, f'列数应为 9，实际 {arr.shape[1]}'
    assert arr.shape[0] > 0, '一行都没读到，检查文件名和表头'
    if skipped:
        print(f'[警告] 共跳过 {skipped} 行非法数据')
    return arr


# ============================================================
# 模块 ②：归一化 —— 每一列压到 [0, 1]
# ============================================================
def normalize_data(train_data, test_data):
    """最小-最大归一化。只用训练集的极值，避免数据泄漏。

    返回归一化后的两个新数组（不修改传入的数组）。
    """
    train_data = train_data.copy()                  # 不改调用者的数据
    test_data = test_data.copy()

    feature_num = train_data.shape[1] - 1           # 前 8 列是特征，最后一列是标签

    max_vals = train_data[:, :feature_num].max(axis=0)
    min_vals = train_data[:, :feature_num].min(axis=0)
    range_vals = max_vals - min_vals
    range_vals[range_vals == 0] = 1                 # 防 0 除 → 防 NaN

    for i in range(feature_num):
        train_data[:, i] = (train_data[:, i] - min_vals[i]) / range_vals[i]
        test_data[:, i] = (test_data[:, i] - min_vals[i]) / range_vals[i]

    return train_data, test_data


# ============================================================
# 模块 ③：数据集提供器 —— 按批吐数据，每轮重新洗牌
# ============================================================
class DatasetProvider:
    def __init__(self, data, batch_size=BATCH_SIZE, shuffle=True):
        self.feature = data[:, :-1]                 # (n, 8)
        self.label = data[:, -1:]                   # (n, 1)  ← 注意冒号，保持二维
        self.batch_size = batch_size
        self.shuffle = shuffle
        self.num_samples = self.feature.shape[0]

    def __iter__(self):
        indices = np.arange(self.num_samples)       # 每轮重建，才能每轮重洗
        if self.shuffle:
            np.random.shuffle(indices)              # 原地打乱，无返回值

        for start_idx in range(0, self.num_samples, self.batch_size):
            end_idx = min(start_idx + self.batch_size, self.num_samples)
            batch_indices = indices[start_idx:end_idx]
            yield self.feature[batch_indices], self.label[batch_indices]

    def __len__(self):
        """一轮有多少个 batch（供打印用）"""
        return (self.num_samples + self.batch_size - 1) // self.batch_size


# ============================================================
# 模块 ④：网络结构 —— 8 → 128 → 64 → 32 → 1
# ============================================================
class MLP(nn.Layer):
    def __init__(self, input_dim):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(input_dim, 128), nn.ReLU(),
            nn.Linear(128, 64), nn.ReLU(),
            nn.Linear(64, 32), nn.ReLU(),
            nn.Linear(32, 1),                       # 回归任务，最后一层不加激活
        )

    def forward(self, x):
        return self.net(x)


# ============================================================
# 模块 ⑤：accuracy —— R²（决定系数），回归任务的通用成绩单
# ============================================================
def accuracy(pred_val, true_val):
    ss_res = paddle.sum(paddle.square(pred_val - true_val))
    ss_tot = paddle.sum(paddle.square(true_val - paddle.mean(true_val)))
    if ss_tot.item() == 0:
        return 1.0 if ss_res.item() == 0 else 0.0
    else:
        r2 = 1.0 - ss_res / ss_tot
    return r2.item()


# ============================================================
# 模块 ⑥：数据准备 —— 加载 + 切分 + 归一化
# ============================================================
def preprocessing(ratio=0.8):
    raw_data = load_data(DATA_FILE)
    offset = int(raw_data.shape[0] * ratio)

    train_raw = raw_data[:offset]
    test_raw = raw_data[offset:]

    train_data, test_data = normalize_data(train_raw, test_raw)

    print(f'训练集形状: {train_data.shape}')
    print(f'测试集形状: {test_data.shape}')
    print(f'归一化数据首行:\n{train_data[0]}')

    return train_data, test_data


# ============================================================
# 模块 ⑦：主流程 —— 训练、评估、保存、推理
# ============================================================
def main():
    np.random.seed(SEED)
    paddle.seed(SEED)

    # 有 GPU 就用 GPU，没有就退回 CPU（换机器不会崩）
    if paddle.is_compiled_with_cuda() and paddle.device.cuda.device_count() > 0:
        paddle.set_device('gpu:0')
    else:
        paddle.set_device('cpu')
    print('训练设备:', paddle.get_device())

    train_data, test_data = preprocessing()

    # 测试集一次性转成张量，后续每轮复用
    X_test = paddle.to_tensor(test_data[:, :-1].astype(np.float32))
    Y_test = paddle.to_tensor(test_data[:, -1:].astype(np.float32))

    model = MLP(input_dim=train_data[:, :-1].shape[1])
    loss_fn = nn.MSELoss()
    optimizer = paddle.optimizer.Adam(learning_rate=LEARNING_RATE,
                                     parameters=model.parameters())
    train_provider = DatasetProvider(train_data, batch_size=BATCH_SIZE, shuffle=True)

    print(f'\n开始训练（{NUM_EPOCHS} 轮，每轮 {len(train_provider)} 个 batch）')

    for epoch in range(NUM_EPOCHS):
        model.train()
        epoch_loss, epoch_acc, n_batches = 0.0, 0.0, 0

        for batch_x, batch_y in train_provider:
            batch_x = paddle.to_tensor(batch_x.astype(np.float32))
            batch_y = paddle.to_tensor(batch_y.astype(np.float32))

            pred = model(batch_x)                   # ① 前向
            loss = loss_fn(pred, batch_y)           # ② 损失
            loss.backward()                         # ③ 反向
            optimizer.step()                        # ④ 更新
            optimizer.clear_grad()                  # ⑤ 清零

            epoch_loss += loss.item()
            epoch_acc += accuracy(pred, batch_y)
            n_batches += 1

        model.eval()
        with paddle.no_grad():
            test_pred = model(X_test)
            test_loss = loss_fn(test_pred, Y_test).item()
            test_acc = accuracy(test_pred, Y_test)

        if (epoch + 1) % 10 == 0 or epoch == 0:
            print(f'Epoch {epoch + 1:3d}/{NUM_EPOCHS} | '
                  f'Train Loss={epoch_loss / n_batches:.4f} '
                  f'Train Acc={epoch_acc / n_batches:.4f} | '
                  f'Test Loss={test_loss:.4f} '
                  f'Test Acc={test_acc:.4f}')

    # ---------- 保存参数 ----------
    print('\n训练完成，保存模型参数')
    paddle.save(model.state_dict(), MODEL_FILE)

    # ---------- 推理：随机抽 1 条测试数据 ----------
    print('\n执行推理过程（从测试集随机抽取 1 条数据）:')
    infer_model = MLP(input_dim=train_data[:, :-1].shape[1])
    infer_model.set_dict(paddle.load(MODEL_FILE))
    infer_model.eval()

    idx = np.random.randint(0, len(test_data))
    assert 0 <= idx < len(test_data), f'下标越界: {idx}'

    single_x = paddle.to_tensor(
        test_data[idx, :-1].reshape(1, -1).astype(np.float32)
    )
    true_age = test_data[idx, -1]

    print(f'选取的数据: {single_x}')
    print(f'真实年龄: {true_age}')

    with paddle.no_grad():
        pred_age = infer_model(single_x).item()

    print(f'预测年龄: {pred_age:.2f} (保留两位小数)')


if __name__ == '__main__':
    main()
```

### 关于 `min_vals` / `max_vals` 的讨论

源码的 `preprocessing()` 返回了 `min_vals, max_vals`，但 `main()` 里是这样接收的：

```python
train_data, test_data, min_vals, max_vals = preprocessing()
```

**接住了，然后……再也没用过。** 这两个变量在后续 100 行里一次都没出现。

那它为什么还要返回？

> **Q：既然没用，是不是可以删掉？**
>
> **A：** **在"这一关的作业"里可以删；在"真实项目"里绝不能删。**
>
> 原因在 1.9 节说过：**归一化的参数是"模型的一部分"**。
>
> 真实上线时的流程是：
>
> ```text
> 训练阶段：算 min_vals / range_vals → 归一化训练集 → 训练 → 存模型
>          ↑ 必须把 min_vals / range_vals 一起存下来
>
> 推理阶段：来一条新数据 → 用"存下来的" min_vals / range_vals 归一化 → 喂模型 → 得到预测
> ```
>
> 如果你推理时用的是"新数据自己的最小值"，那就和训练时的尺度不一致了，预测会偏得离谱。
>
> **所以那两个返回值不是冗余，是"设计者已经想到了未来，只是这一关用不上"。** 这是好代码的特征。
>
> 顺便说：本书的完整版把 `preprocessing` 的返回值缩减成两个（`train_data, test_data`），是为了让示例更短。**如果你要在报告里显得专业，建议把那两个极值也返回并打印出来**，说明"这些参数会随模型一起保存"。

## 1.20 常见错误排查（从启动到推理，按出错顺序排）

下面每一条报错**都是我真实触发过的**，不是从别处抄的。

### 阶段一：程序刚启动

**① `ModuleNotFoundError: No module named 'paddle'`**

```text
【实测输出】
  File "<string>", line 1, in <module>
    import paddle
ModuleNotFoundError: No module named 'paddle'
```

**原因**：没装 paddle，或者装到了另一个 Python 环境里。

**排查**：
```bash
python -c "import paddle; print(paddle.__version__)"
```
如果这条命令报同样的错，说明当前 `python` 里确实没有。装命令（GPU 版按你的 CUDA 版本选）：
```bash
python -m pip install paddlepaddle-gpu
```

⚠️ **最常见的坑**：装了 Anaconda，但用系统的 `python` 运行。检查 `where python` 输出的第一个是不是你以为的那个。

**② `FileNotFoundError: ... 'abalone.data'`**

```text
【实测输出】
FileNotFoundError: [Errno 2] No such file or directory: 'abalone.data'
```

**原因**：文件名写错（真实文件叫 `10abalone.data`，1.4 节详述）。

**排查**：`os.listdir('.')` 看一眼当前目录里到底有什么。**注意"当前工作目录"不等于"脚本所在目录"**——如果你在别的目录下用 `python D:/xxx/脚本.py` 运行，`open('相对路径')` 是相对那个目录的。

**③ `ValueError: (InvalidArgument) use wrong place, Please check.`**

```text
【实测输出 · 机器上没有可用 GPU】
is_compiled_with_cuda = True
device_count = 0
ValueError: (InvalidArgument) use wrong place, Please check. (at ..\paddle\fluid\pybind\place.cc:428)
```

**原因**：调了 `set_device("gpu:0")` 但找不到 GPU。

**排查**：先跑 `nvidia-smi`。命令不存在 → 驱动没装；命令正常但 `device_count()` 是 0 → paddle 版本或 CUDA 版本不匹配。

### 阶段二：数据加载

**④ 读到 `(0,)`，后面莫名其妙报错**

```text
【实测输出】
  加表头 -> 读到行数 = (0,)
```

**原因**：文件有表头，`load_data` 第一行就 `break` 了。

**排查**：`print(arr.shape)`。只要不是 `(4177, 9)`，就先查数据。

**⑤ 读到 `(1, 8)` 或 `(n, 8)`，列数不对**

```text
【实测输出】
  少一列 -> shape = (1, 8)
```

**原因**：某行少一个字段，程序照样收了。

**后果**：`data[:, -1]` 取到的是"克重"而不是"环数"，模型会去预测 0~1 之间的数，loss 小得可疑。

**排查**：`assert arr.shape[1] == 9`。

**⑥ `ValueError: setting an array element with a sequence... inhomogeneous shape`**

```text
【实测输出】
ValueError: setting an array element with a sequence. The requested array has an inhomogeneous shape after 1 dimensions. The detected shape was (2,) + inhomogeneous part.
```

**原因**：不同行的列数不一样，numpy 拒绝拼成矩阵。

**这个错是好事**，它帮你抓住了脏数据。

**⑦ `ValueError: could not convert string to float: ''`**

```text
【实测输出】
  空字段 -> ValueError: could not convert string to float: ''
```

**原因**：某个字段是空的（`M,0.455,,0.095,...`）。

**排查**：给 `float()` 包 `try/except`，或者先 `strip()` 再判断空字符串。

### 阶段三：训练

**⑧ `AttributeError: 'Linear' object has no attribute 'clear_grad'`**

```text
【实测输出】
lin.clear_grad() -> AttributeError: 'Linear' object has no attribute 'clear_grad'
```

**原因**：层的清梯度方法叫 `clear_gradients()`（带 s），优化器的叫 `clear_grad()`（不带 s）。

**⑨ `Train Loss=nan`**

```text
【实测输出 · 学习率过大】
--- lr=1000.0 ---
  epoch 1: Train Loss=1370065302307056456302840571232256.0000
  epoch 2: Train Loss=1383863108995795250558862062780416.0000
  epoch 3: Train Loss=1381786849976321328088342012624896.0000
--- lr=100000.0 ---
  epoch 1: Train Loss=nan
  epoch 2: Train Loss=nan
  epoch 3: Train Loss=nan
```

**原因**：学习率太大了。看第一组数据——`1.37e33`，一个天文数字，说明参数已经飞出天际了。再大一点就直接 `nan`。

**注意**：`nan` 是**不可逆**的。一旦出现，后面的 epoch 全是 `nan`，因为 `nan` 参与任何运算还是 `nan`。

**排查顺序**：
1. 学习率是不是写成了 `1e-1` 或者 `1000`？（源码是 `1e-3`）
2. 数据归一化了吗？（没归一化时，`2.8` 量级的输入配上大学习率很容易炸）
3. 标签列是不是取错了？（比如取到了含负数的列）

**⑩ `Train Loss` 几十轮都不降**

对照 1.17 节的学习率表：`lr=1e-5` 时 20 轮只从 111.27 降到 95.20。**先把学习率调大 100 倍试试。**

**⑪ R² 是个大负数（比如 -8、-10），一直不涨**

`batch_size=3341` 时实测就是这个结果（1.17 节，R²=-8.9159）。模型几乎没被更新时，预测值离谱到远超"猜均值"的水平，R² = 1 - SS_res/SS_tot 就给出大负数。因为一轮只更新 1 次，20 轮只更新 20 次。**检查 batch_size 是不是被误设成了整个数据集的大小。**（反过来这也是 R² 的优点：负数一眼就能看出"没学到东西"，不用像 loss 那样先知道基线才能判断。）

### 阶段四：保存与推理

**⑫ `ValueError: The ``path`` (...) to load model not exists.`**

```text
【实测输出】
ValueError: The ``path`` (not_exist.pdparams) to load model not exists.
```

**原因**：模型文件不存在。可能训练没跑到 `paddle.save` 那一步就崩了，或者路径不对。

**⑬ `IndexError: index 836 is out of bounds for axis 0 with size 836`**

```text
【实测输出】
真的用 idx=836 去索引 -> IndexError: index 836 is out of bounds for axis 0 with size 836
```

**原因**：用了标准库的 `random.randint(0, len(test_data))`（闭区间），取到了 836。

**注意**：这个 bug 只有 1/836 的概率触发，**跑 100 次可能都不出现，答辩现场一跑就崩**。这是最需要防的一类错误。

**⑭ 推理预测值全是 9 点几**

这不是报错，但很常见。原因见 1.18 节：MSE 损失会让模型"向均值收缩"，预测值标准差（2.240）明显小于真实值（2.690）。

**这说明模型学到的是"趋势"而不是"精确值"**，属于正常现象。想改善需要更多特征或换模型，调网络层数没用。

### 一条查不到的报错

**`RuntimeError: CUDA out of memory`**

【未实测说明】这条我**无法在本机复现**——8 GB 显存放得下这个 11521 参数的小模型，无论怎么调都不会溢出。

它的典型样子是：`RuntimeError: ResourceExhaustedError: Out of memory error on GPU 0. Cannot allocate xxx MB memory...`

如果真的遇到，处理顺序：① 减小 `batch_size`；② 确认评估段有 `with paddle.no_grad():`；③ 关掉其他占显存的程序。

### 答案

**1.** 公式：$x' = (x - x_{\min}) / (x_{\max} - x_{\min})$。
直接除以最大值（$x/x_{\max}$）虽然也能把范围压到 `[0,1]` 以内，但**最小值不一定落在 0**。减最小值的作用是把整列平移到从 0 开始，这样 8 个特征才真正站在同一起跑线上。

**2.** ① 用测试集自己的极值等于在训练阶段就"偷看"了测试数据的分布，属于**数据泄漏**，成绩会虚高。② 真实上线时拿不到"未来数据的极值"，你唯一能用的就是训练时记下的 `min_vals` 和 `range_vals`。所以归一化参数属于"模型的一部分"，必须随模型保存。

**3.** `range_vals` 为 0。源码用 `range_vals[range_vals == 0] = 1` 兜底，结果这一列全变成 0（因为 `x == min`）。不处理的话会 `(x - min) / 0` 得到 `nan`，而 `nan` 会顺着梯度传播，几轮后 loss 变 `nan`，模型彻底死掉。

**4.** `data[:, -1]` 形状是 `(n,)`（一维），`data[:, -1:]` 形状是 `(n, 1)`（二维）。模型输出是 `(batch, 1)`，如果标签是 `(batch,)`，`pred - true` 会广播成 `(batch, batch)`，loss 变成一个巨大的数，**而且不报错**。

**5.** `3341 / 64 = 52.2`，向上取整 **53 个 batch**。前 52 个各 64 条（3328 条），最后一个 `3341 - 3328 = 13` 条。

**6.** 因为洗牌必须**每一轮重新做一次**。写在 `__init__` 里就只在对象创建时洗一次，之后每轮顺序都一样，`shuffle=True` 就失效了。规则：每个 epoch 要重置的东西放 `__iter__`，整个生命周期只算一次的放 `__init__`。

**7.** 没有返回值，返回 `None`（原地修改）。写成 `a = np.random.shuffle(a)` 会让 `a` 变成 `None`，下一行切片就报 `TypeError: 'NoneType' object is not subscriptable`。

**8.** 一共 **11521** 个。
- `Linear(8, 128)`：8×128 + 128 = 1152
- `Linear(128, 64)`：128×64 + 64 = 8256
- `Linear(64, 32)`：64×32 + 32 = 2080
- `Linear(32, 1)`：32×1 + 1 = 33
- 合计：1152 + 8256 + 2080 + 33 = 11521

**9.** 因为 ReLU 会把负数变成 0，而回归任务的输出在训练过程中完全可能是负数。更严重的是**梯度问题**：如果某样本预测值一开始是负的，ReLU 会把它掐成 0 且梯度恒为 0，这个样本就"永远学不动"了（神经元死亡）。一般规则：回归不加激活，二分类加 Sigmoid，多分类加 Softmax。

**10.** 默认是 `'mean'`（除以元素个数）。这很重要，因为**它让 loss 的量级与 batch_size 无关**。如果默认是 `'sum'`，把 batch 从 64 改成 16，loss 会变成 1/4，你会误以为模型突然变好了。

**11.** 因为 R² 的分母 $\sum(y - \bar y)^2$ 需要**一批标签的"波动"**才有意义——它是"这个集合里标签差异有多大"。只有 1 条样本时，它自己就是自己的均值，分母为 0，公式直接除零（1.14 节实测过：单条样本没有 R² 这个概念）。
源码的兜底：`if ss_tot.item() == 0:` 返回 1.0（预测也完全对）或 0.0（预测错）。但要注意这只防"除零崩溃"，防不住"小集合 R² 波动大"——实测 53 个 batch 的 R² 从 -1.16 到 0.82 都有，所以 **R² 一定要在足够大的集合（比如整个测试集）上算才可信**。

**12.** 五步：
```python
pred = model(batch_x)          # 前向
loss = loss_fn(pred, batch_y)  # 损失
loss.backward()                # 反向
optimizer.step()               # 更新
optimizer.clear_grad()         # 清零
```
忘了清零，梯度会**累加**（实测第二次恰好是第一次的 2 倍）。第 k 批的梯度会变成前 k 批的总和，越来越大步，最后发散成 `nan`。

**13.** `optimizer.clear_grad()` 是优化器的方法（不带 s），清的是所有参数的梯度；`layer.clear_gradients()` 是层的方法（带 s）。写错会报 `AttributeError: 'Linear' object has no attribute 'clear_grad'`。

**14.** **可能，而且这份代码里就是这样。** 不是"滑动平均"造成的（实测用最终参数在训练集上一次性算，MSE 仍是 4.5631）。
真正原因是**测试集比训练集"简单"**：测试集环数方差 7.236，训练集 11.126；测试集最大 21 环，训练集最大 29 环。MSE 对"本身差异小"的集合天然给低分。
注意别拿日志里的 Train Acc（batch 平均 R²，0.5763）和 Test Acc（整体 R²，0.5383）直接比——它们口径不同（见 1.14 节）。

**15.** 用 $R^2 = 1 - \text{MSE}/\text{方差}$——**源码的 `accuracy` 本身就是它**，拿最终模型在两个集合上整体各算一次即可。
- 训练集：$1 - 4.5631/11.1262 = 0.5899$
- 测试集：$1 - 3.3409/7.2356 = 0.5383$
按 $R^2$ 看，测试集确实略差——这才符合直觉。

**16.** **没有区别。** 实测两种模式下输出逐位相同，因为网络里只有 `Linear` 和 `ReLU`，行为不随模式改变。
仍然要写的原因：一旦以后加了 `Dropout` 或 `BatchNorm`，这两行就变成生死攸关。忘了在评估前调 `eval()`，Dropout 还在随机丢，测试成绩会偏低且每次都不同。

**17.** **这个模型上 CPU 更快**（实测 0.43s vs 0.96s，CPU 快 2.25 倍）。
因为单批计算量太小（`64×8 @ 8×128`），"显存搬运 + 核函数启动"的固定开销超过了计算本身。
GPU 明显更快的条件：`batch_size` 大（实测全量一批时 GPU 快 10.33 倍）、模型宽/深（实测 512-256-128 时快 93.94 倍）、图像/大语言模型等真正大的任务。

**18.** 报 `ValueError: (InvalidArgument) use wrong place, Please check.`，同时标准错误里有 `Cannot use GPU because there is no GPU detected on your machine.`

**19.** `lr=1e-5`：几乎学不动。实测 20 轮 loss 只从 111.27 降到 95.20，R²=-10.26（比瞎猜还差 10 倍）。
`lr=1000`：loss 爆炸，实测第 1 轮就 `1.37e33`；设成 `1e5` 直接变成 `nan`。

**20.** `bs=3341` 时一轮只有 1 次参数更新，20 轮总共 20 次更新，模型基本还在初始化原地。实测 `Train Loss=86.6709`、`Test Acc(R²)=-8.9159`——大负数，**等于没训练**。

**21.** **8 个键**：4 个 Linear 各有一对 `weight` 和 `bias`，共 `net.0/2/4/6` 各 2 个。
ReLU 没有键，因为**它没有可学习的参数**——它只是一个固定的 `max(0, x)` 运算。

**22.** `test_data[idx, :-1]` 的形状是 `(8,)`（一维），而网络要求输入 `(batch, 8)`。`reshape(1, -1)` 变成 `(1, 8)`，表示"1 条样本，8 个特征"。`-1` 表示"这一维你自动推算"。

**23.** `np.random.randint(0, 836)` **取不到 836**（上界是开区间，最大 835）。`random.randint(0, 836)` **能取到 836**（闭区间）。
源码用的是 numpy 版，所以没有越界 bug。如果手滑换成标准库版，就会以 1/836 的概率报 `IndexError`。

**24.** 追问三个：
1. **"指标是怎么定义的？"** 同一份预测，实测可以算出 0.2895（四舍五入相等）、0.5383（R²）、0.5251（误差≤1）、0.7990（误差≤2）四个数；分类任务的 90% 和回归任务的 R²=0.9 更是完全不同的东西。
2. **"在哪个集合上算的？"** 训练集上的 90% 和测试集上的 90% 完全不是一回事。
3. **"基线是多少？"** 如果永远猜众数/均值就能有 85%，那 90% 几乎等于没学到东西。（R² 天生带基线：0 分 = 猜均值，这也是回归任务爱用它报成绩的原因。）

### 答辩可能被问到的四个问题

**Q：你的 R² 0.54 是什么意思？是不是"答对了 54%"？**
> 不是。R² 的定义是 $1 - \frac{\sum(\hat y - y)^2}{\sum(y - \bar y)^2}$：分母是"无脑猜均值"的误差，分子是模型的误差。0.5383 的意思是**模型把"猜均值"的误差消化掉了 54%**，也可以说解释了测试集 54% 的波动。
> 参照系：猜均值恰好得 0 分；完美预测得 1 分；比瞎猜还差是负数（第 1 轮训练时我的日志里就是 -0.25）。
> 作为"说人话"的对照：四舍五入完全命中的比例是 0.29；误差 ≤1 环的比例是 0.525；平均绝对误差 MAE 是 1.31 环。

**Q：日志里的 Train Acc 和 Test Acc 可以直接比较吗？**
> **不能直接比，口径不同。** Train Acc 是 53 个 batch 各自算 R² 再平均（batch 口径，第 100 轮 0.5763）；Test Acc 是 836 条测试集整体算的 R²（整体口径，0.5383）。逐 batch 平均的 R² 没有清晰含义——实测同一模型同一训练集，整体口径是 0.5899，batch 平均口径只有 0.2898（每个 64 条的小 batch 方差波动太大）。
> 公平的比较要用整体口径各算一次：训练集 0.5899 vs 测试集 0.5383，测试集确实略差，符合直觉。
> 根本原因是**顺序切分**：取前 80% 训练、后 20% 测试，没打乱，两个集合分布不一致。换成随机切分后 R² 是 0.5237，那才是模型的真实水平。

**Q：为什么不用 GPU 加速？**
> 用了（`paddle.get_device()` 输出 `gpu:0`）。但这个模型只有 11521 个参数、每批 64×8 数据，单次计算量太小，显存搬运和核函数启动的固定开销占了主导。我实测过：这个规模下 CPU 反而快 2.25 倍；把 batch 提到全量、网络加宽到 512-256-128 后，GPU 快 94 倍。

**Q：怎么改进这个模型？**
> 三个方向，按性价比排序：
> 1. **加特征**：现在只有 8 个体型特征，$R^2$ 只有 0.54，说明一半以上的波动解释不了。这是最大的瓶颈。
> 2. **sex 改独热编码**：概念上更正确（避免把类别当连续量），实测差异在噪声范围内但值得做。
> 3. **随机切分 + 早停**：让评估更可信，避免无意义的训练轮数。
>
> 单纯加宽网络（比如 512-256-128）不会有明显提升，因为瓶颈在特征不在容量。
